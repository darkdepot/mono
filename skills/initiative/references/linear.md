# Инициатива в Linear

Ссылки по `<корень>/references/linear-links.md`: проект голым `P-<TEAM>-N`,
инициатива и документ `[точное название](<url>)`. Сопоставляй по `id`, не по
названию. Служебные файлы пиши командой оболочки в `$TMPDIR`.

## Чтение

Команда продукта: `linearTeam` из `<конфиг>`. Нет доступа к инициативам,
документам, комментариям или проектам Linear: скажи, чего не хватает; локальный
файл за сохранённую инициативу не выдавай.

По сырой идее найди похожие инициативы и проекты (все страницы, полные
описания кандидатов). Подходящая есть: назови её и продолжай её, дубль не
заводи; несколько правдоподобных — спроси владельца. У найденной инициативы
прочитай описание (`get_initiative` с `includeProjects`), документы через
`list_documents` по инициативе, все комментарии и тела привязанных проектов.
Старая инициатива с целью, моделью и картой в «Решении» — это материал для
черновика, не отменённое решение: действующее утверждение проверяет команда ниже.

## Сохранение черновика

Перед первым показом создай инициативу в Proposed (владелец инициативы —
владелец, команда продукта) или обнови найденную. Прежнее описание черновика,
если оно не по шести частям, сохрани целиком документом «Прежнее описание:
<инициатива>» до замены. Документ «Решение: <инициатива>» привязан к инициативе.
Каждую запись читай обратно. Правка после показа — запись, обратное чтение и
новый показ изменённого; мелкая поправка по общему правилу `owner-dialog.md`.

## Утверждение

Перед показом сохрани в одну папку сырые ответы обратного чтения:
`initiative.json` (`get_initiative`, `includeProjects`, статус строкой),
`decision.json` (документ «Решение» с `id`, `content` и id инициативы), все
страницы комментариев инициативы `comments-N.json` с запросами
`comments-N.request.json` (первый `{}`, затем cursor прошлого ответа, до
`hasNextPage=false`). Хеши описания и «Решения» считай из этих файлов:

```bash
node --input-type=module -e 'import { initiativeFingerprint as f } from "<корень>/scripts/idea-gate.mjs"; import { readFileSync as r } from "node:fs"; const j = JSON.parse(r(process.argv[1], "utf8")); console.log(f(j.description ?? j.content))' <файл>.json
```

После ясного согласия внеси названную мелкую поправку, если она есть, затем
перечитай обе части и пересчитай хеши. Совпали с показанными или изменились
только этой поправкой: один комментарий с хешами последнего чтения на инициативе, первая строка внутри забора `text`:

```text
mono-initiative: approved initiative=<uuid> brief-sha256=<хеш описания> decision=<uuid> decision-sha256=<хеш решения> by=owner
```

Вне забора строка «Владелец: ответил «<его слова дословно>»», при мелкой
поправке ещё «Поправка: <что изменено>». Не совпали: покажи «Было / Стало» и
спроси заново, записи нет. Затем обнови дамп комментариев и проверь:

```bash
node <корень>/scripts/idea-gate.mjs initiative --mode fresh --dump <папка> --config <конфиг>
```

Нужен exit 0 и `code=pass`. `stale-brief`/`stale-decision` — версия изменилась,
новый показ. `no-record` — утверждения нет. `bad-record` — проверь форму записи и
файлы дампа. Сбой записи: перечитай комментарии, недостающее повтори один раз;
снова нет — скажи, что не записано.

Первое утверждение переводит Proposed в Planned; позже статус инициативы этап
не меняет. Согласие на карту записывается так же: карта в «Решении», обратное
чтение, показ, новый комментарий той же формы. Проекты создаются только после
`pass` на версии с картой. Если после утверждения инициативы в «Решении» уже
есть карта, а более новой записи нет, `stale-decision` значит «карта ждёт
согласия»: покажи карту, не всю инициативу заново.

## Карта в «Решении»

Раздел «Карта проектов»: каждый пункт один элемент списка, поля строками с
отступом под ним, без таблиц и вложенных списков. Так строка «Заведён», дописанная
после создания, не меняет хеш. Номер постоянный, не перенумеровывай ради
удаления другого. Например:

* К1. Владелец видит всех людей из переписки с описаниями
  Ценность: агент и владелец знают, кто есть кто, без папки проекта.
  Проверяет: что описания реально помогают агенту отвечать.
  Зависимости: нет
  Приоритет: High
* К2. Агент сам предлагает описания новым людям
  Ценность: база не пустеет, владелец только подтверждает.
  Зависимости: К1
  Приоритет: Normal

Зависимости только на более ранние номера. Приоритет из значений Linear.
Существующий проект становится пунктом только после признания владельцем:
строка «Есть проект: P-<TEAM>-N» до показа.

## Создание проектов

Перед записью прочитай `<корень>/references/contracts/project.md`. По пунктам в
порядке номеров:

1. Есть строка «Есть проект» или «Заведён»: проверь проект по `id` и привязку к
   инициативе; нет привязки — добавь. Существующему признанному проекту только
   привязка и приоритет; зависимость комментарием на проекте «Зависит от:
   P-<TEAM>-N, …» (или «Зависит от: нет»), если последний такой иной; тело и
   статус не трогай.
2. Строки нет: сначала поищи среди проектов инициативы `К<n>` со ссылкой на эту
   инициативу в теле или в «Отброшено» брифа (`<корень>/references/brief.md`).
   Нашёлся один — допиши «Заведён», не создавай. Несколько — спроси владельца.
3. Не нашёлся: один `save_project`: имя пункта, команда продукта, статус Idea,
   `lead` владелец, приоритет пункта, `addInitiatives` с инициативой, тело
   строкой `[точное название инициативы](<url>) — К<n>: <ценность>` и, если есть
   зависимости, второй строкой «Зависит от: P-<TEAM>-N, …». Прочитай обратно,
   сразу допиши в пункт «Решения» строку с отступом «Заведён: P-<TEAM>-N» и прочитай
   документ. Потерян ответ create — сначала поиск, не повторный create.

Карта изменилась после создания части проектов: новые пункты создай, строку
«Зависит от» у заведённых этапом проектов приведи к новой карте: допиши,
перепиши или удали, пока тело ещё состоит только из строки пункта и, может быть,
строки «Зависит от». Тело, уже заменённое своим Idea, не трогай. Проект снятого пункта не трогай и назови в итоге.

## Состояния проектов при повторном входе

Сначала статус из Linear: Canceled — отменён; Completed — завершён; Discovery,
Ready, Delivery и дальше — в работе; Idea с годной записью Idea — разрешён к
запуску; Idea без неё — заведён, ждёт своего Idea; пункт без проекта —
предложен. Иное назови как есть. Завершение всех проектов не закрывает
инициативу и не доказывает результат.
