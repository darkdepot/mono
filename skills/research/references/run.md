# Как запускать: вход, разведчики, вторая модель

Справка для разделов 1, 3, 5 и 8 скилла. Команды запускай из папки продукта.
Рабочая папка: `<папка>` = `$TMPDIR/mono-research/<короткое имя проекта>/`;
в продукт ничего не кладёшь.

## Вход

До проверки идеи найди или заведи задачу `Research: <проект>` по
[правилам задач этапов](<корень>/references/lifecycle.md#задачи-этапов).
Отказ входа: причина и куда дальше в её комментарии, задача закрыта в Done,
обратное чтение. Не можешь писать в Linear: остановись с причиной, не заявляй,
что задача создана или закрыта. Исключение «до Research» тоже запиши в задаче
и закрой её; исследования задним числом не делай.

Прочитай проект и все страницы его комментариев и сохрани ответы Linear как есть
в `<папка>/linear/`: `project.json`; на каждую страницу комментариев `comments-N.json`
и `comments-N.request.json` (`{}` для первой, `{"cursor":"<курсор прошлого ответа>"}`
дальше). Ничего в них не правь.

```bash
node <корень>/scripts/idea-gate.mjs check --mode fresh --dump <папка>/linear --config <конфиг>
```

Решает код в строке `idea-gate: <pass|fail>: <код> project=<id>`, а не код выхода:
`stale` печатается как `fail`, но этап начинается.

| Код | Что делать |
|---|---|
| `pass` | Начинай. |
| `stale` | Начинай. В шапке документа: «описание менялось после «да»». Неизвестные бери из записи «да»: их исследуешь ты, по ним Discovery запишет решения в PRD. |
| `legacy-migrate` | Старый проект без записи. Начинай, вопросы брифа бери из описания проекта; в шапке «до записи Idea». |
| `no-record`, `bad-record`, `other-project` | Годной записи «да» нет: этап не начинается. Одной строкой владельцу или оркестратору: идея не одобрена, нужен этап Idea с владельцем (код). |
| другое | Стоп: назови код и что сделать. |

Проект ещё в статусе Idea: этап Idea не закончен, вернись в `mono:idea`
(закончить статус и проверку этапа). Пакет проекта одобрен до даты выпуска
(`researchGate.since` из конфига, иначе `RESEARCH_GATE_DEFAULT_SINCE` из `<корень>/scripts/idea-gate.mjs`): исследование задним числом не делаем, скажи об этом.
Одобрен позже без исследования: исследуй, Handoff потом обновит одобрение.

## Разведчики

Модель и усилие выдаёт:

```bash
node <корень>/scripts/idea-gate.mjs helper --host claude-code|codex --config <конфиг>
```

- Claude Code: агенты `mono:linear-scout`, `mono:code-scout`, `mono:web-scout`
  с этой моделью, все вызовы круга в одном сообщении.
- Codex: встроенные субагенты с этой моделью и усилием и `fork_turns: "none"`.
  Сообщение каждому: текст его файла из `<корень>/agents/` без шапки и текст задания.
  Дождись всех. Модель не принята: повтори без неё.

Каждому передай: задание (`references/find-in-linear.md`, `references/find-in-code.md`
или раздел `references/find-on-web.md`), вопросы (внутренним все вопросы брифа,
внешнему один), бриф, название продукта, ключ команды Linear из конфига, путь
к репозиторию.

Круг: не больше трёх разведчиков сразу (в Codex это предел слотов). Обычный размер:
один круг. Крупный: ещё один круг до трёх по пробелам. Вопросов больше, чем мест:
объединяй их в одно задание на источник.

Разведчик недоступен или вернул пустой итог: собери его часть сам и отметь в технике.
Поиска в интернете в сессии нет совсем: в шапке «снаружи не смотрели: нет поиска»,
ответы по внутренним фактам.

Данные продукта: только источники этого продукта, названные в проекте или в конфиге
(аналитика, поддержка, журналы и папки заметок, на которые ссылается проект).
Другие подключения сессии (другие продукты, почта, личные сервисы) не трогай.

Когда этап ведёт оркестратор: сверяй в источнике не больше трёх ключевых фактов,
по цитате, а не всей страницей.

## Вторая модель

Один проход без диалога, модель другой семьи: Claude Code — роль `second-voice`,
Codex — роль `second-voice-alt`; модель и усилие роли по
`<корень>/references/model-policy.md`. Запуск в фоне, только на чтение:
из Claude Code `codex exec -m <модель> -c model_reasoning_effort=<усилие> -s read-only
"<вопрос>" < /dev/null`, из Codex `claude -p --model <модель> --effort <усилие>
"<вопрос>" < /dev/null`. Из Codex второй модели нужна сеть. Вход: черновик документа
и выдержки источников, на которых держится совет. Вопрос: где натяжка, что
пропущено, где вывод выдан за факт, какой контрпример не учтён.

Не запустилась или не ответила: в шапке «без второго мнения», заменой той же моделью
не подменяй.
