# Как запускать: вход, разведчики, вторая модель

Справка для разделов 1, 3, 5 и 7 скилла. Команды запускай из папки продукта.
Рабочая папка: `<папка>` = `$TMPDIR/mono-research/<короткое имя проекта>/`;
в продукт ничего не кладёшь.

## Вход

Вход проверяется только чтением, до записей в Linear. Отказ: одной строкой владельцу
или оркестратору, почему и куда дальше; без задачи этапа и записей. Исключение
«до Research» тоже строкой в сессии; исследования задним числом не делай.

Прочитай проект и все страницы его комментариев и сохрани ответы Linear как есть
в `<папка>/linear/`: `project.json`; на каждую страницу комментариев `comments-N.json`
и `comments-N.request.json` (`{}` для первой, `{"cursor":"<курсор прошлого ответа>"}`
дальше). Ничего в них не правь.

```bash
node <корень>/scripts/idea-gate.mjs check --mode fresh --dump <папка>/linear --config <конфиг>
```

Решает код в строке `idea-gate: <pass|fail>: <код> project=<id>`, а не код выхода.

Делегированный проект: `stale`/`legacy-migrate` останавливает автономный старт
Research и работы. Оркестратор несёт идею владельцу; до его кнопки, новой записи
и свежей проверки не начинай, сам снимок не переутверждай.

Проект в статусе Idea: допуск только при `pass` и старте от владельца (кнопка
«Начать исследование» или его слова), либо стартом оркестратора в делегированном
проекте по отметке последней идеи или прежнему явному решению владельца.
Другой код или старта нет: проект остаётся
в Idea, без записей, дальше `mono:idea`. Таблица ниже для проектов уже после Idea;
там `stale` печатается как `fail`, но этап начинается.

| Код | Что делать |
|---|---|
| `pass` | Начинай. |
| `stale` | Начинай. В «Как искали»: «описание менялось после утверждения». Неизвестные бери из записи: по ним следующий этап запишет решения в PRD. |
| `legacy-migrate` | Старый проект без записи. Начинай, вопросы бери из описания; в «Как искали» «до записи Idea». |
| `no-record`, `bad-record`, `other-project` | Годной записи нет: этап не начинается. Одной строкой: идея не утверждена, нужен этап Idea с владельцем. |
| другое | Стоп: назови код и что сделать. |

Пакет проекта одобрен до даты выпуска (`researchGate.since` из конфига, иначе
`RESEARCH_GATE_DEFAULT_SINCE` из `<корень>/scripts/idea-gate.mjs`): исследование
задним числом не делаем, скажи об этом. Одобрен позже без исследования: исследуй,
Handoff потом обновит одобрение.

Переход из Idea (проверка перехода по контракту проекта): после допуска статус
Discovery и чтение обратно, молча; не сохранилось, повтори один раз; снова нет:
стоп, скажи, что статус не сменился. Только после подтверждённого Discovery найди
или заведи задачу `Research: <проект>` по
[правилам задач этапов](<корень>/references/lifecycle.md#задачи-этапов) и запиши
в журнал код проверки, кто и как начал, статус до и после. Проект уже после Idea:
задача сразу после допуска. Не можешь писать в Linear: стоп с причиной.

## Разведчики

Модель и усилие выдаёт:

```bash
node <корень>/scripts/idea-gate.mjs helper --host claude-code|codex --config <конфиг>
```

- Claude Code: агенты `mono:linear-scout`, `mono:code-scout`, `mono:web-scout`
  с этой моделью, `run_in_background: true`, весь круг в одном сообщении. Ход
  закончи стартовым сообщением. Каждое уведомление: итог направления по `examples.md`,
  ход кончается им. После последнего итога сводишь в том же ходе.
- Codex: встроенные субагенты с этой моделью и усилием и `fork_turns: "none"`.
  Сообщение каждому: текст его файла из `<корень>/agents/` без шапки и задание.
  Ход не заканчивай: `wait_agent` по оставшимся, вернулся один: итог направления,
  снова `wait_agent`. Модель не принята: повтори без неё.

Каждому передай: задание (`references/find-in-linear.md`, `references/find-in-code.md`
или раздел `references/find-on-web.md`) как есть, без своих подсказок с ответом;
вопросы (внутренним все вопросы брифа, внешнему один), бриф, название продукта,
ключ команды Linear из конфига, путь к репозиторию.

Круг: не больше трёх разведчиков сразу. Обычная глубина: один круг. Большая: ещё
один круг до трёх по пробелам. Вопросов больше, чем мест: одно задание на источник.

Разведчик недоступен, завис или пуст: собери его часть сам, строка в технике.
Поиска в интернете нет: в «Как искали» «снаружи не смотрели: нет поиска».

Данные продукта: только источники этого продукта, названные в проекте или в конфиге.
Другие подключения сессии (другие продукты, почта, личные сервисы) не трогай.

## Вторая модель

Один проход без диалога, модель другой семьи: Claude Code роль `second-voice`,
Codex роль `second-voice-alt`; модель и усилие роли по
`<корень>/references/model-policy.md`. Только на чтение: из Claude Code
`codex exec --ignore-user-config --disable apps -m <модель> -c model_reasoning_effort=<усилие> -s read-only "<вопрос>" < /dev/null`,
из Codex `claude -p --strict-mcp-config --model <модель> --effort <усилие> "<вопрос>" < /dev/null`;
из Codex нужна сеть. С владельцем запускай на переднем плане с таймаутом команды
`600000`, чтобы ход не кончался ожиданием. Вход: черновик и выдержки источников,
на которых держится совет. Вопрос: где натяжка, что пропущено, где вывод выдан
за факт, какой контрпример не учтён.

Не запустилась или не ответила: в «Как искали» «без второго мнения», той же
моделью не подменяй.

## Следующий этап

Сначала определи старый путь по `mono:check discovery`, раздел Old path
(`<корень>/skills/check/SKILL.md`): одобренный пакет прежнего Handoff. Такой проект
идёт в `mono:handoff`, он только чинит этот пакет. Остальные: `mono:discovery`.
Совет «не делать» или «отложить» решается на следующем этапе.
Окно перехода после финала: `references/examples.md`, «Дальше».

Второй модели передавай тексты или локальные пути, не ссылки Linear: подключений владельца у неё нет.
