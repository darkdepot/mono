# Одна страница и её утверждение

До 130 слов обычным текстом, без блоков кода. Страница сама итог, второго
пересказа нет. Описывай поведение и последствия для владельца вместо устройства,
файлов, механизмов и списка PR. Порядок:
1. Вывод: что строим и почему это решение.
2. «Тебе решить»: всегда, даже если «необратимого нет, прежние решения не
   меняются». Иначе назови необратимое, отложенный пункт PRD или прежнее решение,
   которое меняешь, с причиной.
3. Главное поведение, что проверено, что не проверено или риск рядом.
4. «Не берём»: сознательно исключённое с причиной.
5. Завершение страницы «Дальше»: что даст Handoff, ссылка на проект или страницу.

Проверка нашла незакрытый случай: исправь решение до показа, случай назови в
проверенном. Данных нет или доступен только пишущий вызов: «проверить не на чем»,
первая проба в Tech Spec, зависимые работы ждут её. Новый механизм оправдан
только поздно заметным вредом или дорогой сменой; остальное исключи с причиной.

## Утверждение

Все помощники, вторая модель, черновики и проверки до страницы. По
`owner-dialog.md` страница, позиция и один вопрос под ситуацию последним
сообщением хода. Запомни страницу и `updatedAt` PRD. Согласие словами
утверждает; мелкую поправку назови одной строкой, смысловую покажи заново.
После ответа свежий PRD; посторонняя смена — «Было / Стало» и новый показ,
кроме случаев `run.md`. Совпало: запись по `spec.md`. Отсрочка без Handoff;
старт только по вопросу о старте или прямым словам владельца.

## Отложенный пункт

Только пункт PRD: «предлагаю отложить: …, потому что …». Просто не строим
лишний механизм: строка «сознательно не строим», не предложение менять PRD.
После согласия с показанной страницей с отложенным пунктом в том же касании вызови
`mono:discovery`: он переносит ровно этот пункт в «Что не входит в MVP», читает
обратно, пишет `mono-prd: approved`. Сохраняет прежний `next`, на старом пути
по просьбе владельца `next=tech-evaluation`; `by=` по режиму этапа. В режиме
владельца строка «Владелец: ответил «<его слова дословно>»», у оркестратора причина.
Это исключение U5 из сохранения отсутствующего `next=` при повторном
утверждении: явная просьба уже привела проект в этап, а перенос пункта
закрепляет этот маршрут. Повторного показа нет. Discovery дополняет комментарий решений закрытой задачи,
не открывая её. Только после его подтверждённого результата Tech Spec и
`mono-tech` с новым `prd-updatedAt`. Любая посторонняя правка PRD требует
новой страницы. Сам этап PRD не меняет.
