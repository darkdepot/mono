# Вход и повторный вход

Команды из продукта. `<конфиг>` = `.agents/mono-workflow.config.json`;
`<папка>` = `$TMPDIR/mono-tech-evaluation/<короткое имя проекта>/`.
Черновики только здесь, в продукт ничего не клади.

## Вход

До работы `mono:check discovery` (`<корень>/skills/check/SKILL.md`) должен дать
PASS: идея, выбранное исследование и PRD утверждены по его правилам. Отказ:
в задаче этапа причина и куда дальше, затем Done; результат не записывай. Последнюю запись
`mono-prd: approved` и текущий PRD прочитай свежими.

- `next=tech-evaluation`: начинай, если владелец начал этап или ведёт оркестратор.
- Поля `next=` нет: старый путь Tech Evaluation, вход только по явной просьбе
  владельца; точные слова и дату запиши в задаче этапа. Иначе в Handoff.
- `next=handoff`: этап не начинай, дальше Handoff.

Старый путь Discovery без записи PRD не даёт входа. Существующая запись
`mono-tech` нужна при повторном входе: прочитай её страницу и Tech Spec по `spec`,
не по названию. После старта работ действует ремонт, а не переписывание входов.

## Задача этапа

Найди задачу проекта `Tech Evaluation: <проект>` с меткой `Этап`. Открытая:
продолжай; закрытая при повторном входе: открой; отложенная: только по условию
возврата или слову владельца. Нет: создай по `<корень>/templates/stage-task.md`,
исполнитель владелец; нет метки, создай. Правила задач этапов в
`<корень>/references/lifecycle.md`. Запиши входную проверку, кто начал, версию
PRD, источники, прежние решения владельца и открытые вопросы к техлиду.
Один комментарий решений: выбранное и почему; отвергнутое и почему; помощник и
проверенные случаи; вторая модель и разбор; точная страница и её версия;
утверждение; Tech Spec; запись и результат команды. По нему продолжай после
перерыва без нового пересказа. Страница поменялась: явно новая версия.

## Повторный вход

Из Handoff до старта: он вызывает этап, сам не решает, меняется ли страница.
Сверь новый PRD, прежнюю страницу и Tech Spec. Меняется любая строка страницы
(включая проверенное или риск): новая страница, проверка затронутого, утверждение
по режиму, обновлённый Tech Spec и новая запись. Handoff затем заново сверяет
пакет. Не меняется ни одна строка страницы: этап сам фиксирует это с причиной,
при необходимости обновляет Tech Spec в её пределах, читает обратно и пишет
новую `mono-tech` с новым `prd-updatedAt`, точной прежней страницей и прежним
`by=`; нового показа владельцу нет. В журнале ссылка на прежнее утверждение и
вызов Handoff. Это исключение только для повторного входа из Handoff после
правки PRD до старта, не для смены версии во время первого утверждения.

Перед каждой записью перечитай PRD и сравни с версией показанной страницы.
Версия PRD, сменившаяся во время первого утверждения, всегда даёт новую страницу.
Второе и единственное другое исключение: Discovery по уже утверждённой строке
«отложить» меняет ровно названный пункт, по `page.md`; новая версия PRD входит
в запись без повторной карточки. Посторонняя правка вместе с ней исключение
отменяет. Ни свежесть по времени комментария, ни чтение вместо команды записи
не подтверждают.

Находка после старта: через Handoff и `<корень>/references/repair-machine.md`;
меняет страницу, класс 3, остановка исполнителей и новый старт. Этап сам не
продолжает текущую реализацию.
