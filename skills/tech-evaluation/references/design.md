# Макет на входе

Маршрут и все записи дизайна действуют вместе; временного значения нет.

## Вход

Сначала `route`, затем при дизайне в цепи команда `design` на свежих сырых
ответах Linear (`project.json`, полные `comments-N.json` и запросы cursor,
`prd.json`). Только exit 0, «Готово», JSON `pass` разрешают использовать макет.
Предшествующая запись цепи должна указывать `next=tech-evaluation`.
`design=not-needed` макета не даёт; отсутствие поля — старый путь Design,
который не требует нового этапа. Отсутствующая обязательная запись или её
устаревание возвращает в Design, повреждённый маршрут к писавшему этапу.

Прочитай PNG годной `mono-design: approved` из её неизменяемой папки вместе с
продуктом, PRD и прежними решениями. Посмотри картинки, не только ссылку или
описание. Раздел «чем рискуем» проверяет и эти экраны.

## До показа страницы

Макет технически не ложится: верни в Design до показа страницы. В задаче этапа
Design запиши конкретный конфликт и причину; владелец или оркестратор ведёт
новый круг по своему режиму. После новой записи дизайна продолжай техоценку.

Пункт PRD на утверждённых экранах не откладывай строкой «предлагаю отложить».
До показа страницы верни в Design: «предлагаю убрать: …, потому что …» в его
задаче этапа. Это новый круг по R8/R11, а не откладывание по странице. Дизайнер
ведёт правку PRD через Discovery в том же касании (U3), получает утверждение
нового макета и запись, после чего техлид продолжает. Сам PRD не меняй.

Пункта на экранах нет: строка откладывания и утверждение страницы как прежде.
После «Утвердить» в том же касании Discovery меняет только названный пункт,
Design проверяет, что экраны прежние, и пишет новую запись с теми же PNG и новым
`prd-updatedAt` без показа (U12). Затем пишешь Tech Spec и `mono-tech` с новой
записью дизайна. Второй остановки нет; иная правка отменяет исключение.

## Повторный вход

Смена записи дизайна тоже вызывает техлида (`stale-design`). Сам реши, меняется
ли строка утверждённой страницы. Тот же маршрут и прежняя страница: обнови
в пределах страницы Tech Spec при необходимости и запись с новым `design=`,
без показа, с причиной и ссылкой на прежнее утверждение. Страница изменилась:
новая проверка и утверждение по режиму. Смена маршрута PRD снимает нижние записи,
нужен новый показ, а не продление прежней страницы. Первый показ всегда привязан
к своей версии PRD; исключения не разрешают подменить её во время утверждения.

В `mono-tech` `design=<id последней mono-design>|none`, без поля это `none`.
Команда `tech` сравнивает с последней записью проекта; несовпадение
`stale-design`, запись не годна. Сначала запись дизайна, потом техлида.
