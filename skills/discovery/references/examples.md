# Как это звучит

Учебный пример. Идея: заполнять отменённые часы без переписки. Research:
напоминание за день не помогает дальним записям; новые клиенты готовы ждать.
Код: отмена и список желающих.
Данные: 14.10.2026 Ольга отменила 11:00 у Ани в 8:40, Марина ждала это время,
час остался пустым. Кто выбирает замену, не решено.

## Первое сообщение

```text
Хочешь заполнять отменённые часы без ручной переписки мастера. Поправь, если
не так: важен занятый час, а не само напоминание.

Исследование не подтвердило пользу напоминания за день для дальних записей.
В коде уже есть отмена и список желающих: можно предложить время тем, кто ждёт.
В случае Ани это шанс заполнить 11:00 сразу после отмены Ольги в 8:40.

От аудитории зависит число сообщений: кому предлагать освободившийся час?
```

Вопрос: «Кому предлагать час? Советую ждущим дату: меньше лишних сообщений».
- Ждущим эту дату (Recommended): уместнее / меньше желающих
- Всем из листа: больше шансов / больше сообщений

Свободный ответ доступен. Если бы идея уже определила
аудиторию, этого вопроса не было бы: следующим сообщением сразу решения.
Про вторник не спрашиваем: данные прочитаны.

## Позиция на ответ

Владелец выбрал ждущих дату. Способ замены и право выбора клиента ещё не решены.

```text
Тогда предлагаем время только ждущим эту дату: меньше шума, но желающих
может не хватить. Теперь сравню способы занять освободившийся час.
```

## Решения отдельным сообщением

После выбора ждущих дату:

```text
А. Автозаполнение из листа. Час занимает первый ответивший, мастер узнаёт по факту.
Цена: не выбирает замену; нужны желающие.
Б. Мастер выбирает из листа. Контроль остаётся; цена: переписка и необходимость
ответить до начала часа.
В. Запись только на две недели. Меньше дальних неявок; цена: теряем планирующих
заранее, а отмены всё равно оставляют пустые часы.

Рекомендую А: убирает ручную работу. Сильнейший довод против: пока лист пуст,
заполнять некому.

На твоём вторнике 14.10.2026, если бы А уже работал:
8:40 Ольга отменила 11:00 у Ани.
8:41 Марина, ждущая эту дату, получила предложение 11:00.
Согласилась: Аня увидела «В 11:00 вместо Ольги Марина».
Отказалась: время доступно следующему желающему.
Было: час пустой; стало: шанс заполнить без переписки Ани.

Размер: обычное. Какой вариант берём?
```

Позиция и окно по `owner-dialog.md`, порядок от хоста. Вопрос: «Как заполняем час?
Советую А: убирает ручную работу». Варианты со свободным ответом:
- А (Recommended): без переписки / нужен лист
- Б: выбор мастера / ждём его ответа
- В: меньше дальних записей / теряем планирующих заранее

Выбрал Б: покажи его до PRD.
Внешний вид: пример о смысле на данных, вид решает Design.
Оркестратору те же вопрос и подписи последним сообщением хода; ждём выбор.

## Утверждение PRD

Всё служебное закончено; по `owner-dialog.md` итог обычным текстом в чат:

> PRD «Лист ожидания» готов к утверждению.
> Решили: освободившееся окно занимает следующий из листа, мастер узнаёт по факту.
> Не берём: дальние записи и оплату, они не помогают заполнить час.
> Дальше: Design покажет замену в расписании; [PRD](https://linear.app/darkdepot/document/prd-list-ozhidaniya).

Окно по `owner-dialog.md`: суть и совет с причиной, варианты с пользой и ценой: «Утвердить и начать Design» / «Утвердить, продолжу позже» /
«Ещё обсудить». После записи и проверки: «Утверждение записал, открываю сессию дизайнера».
Правка, в том числе из Handoff: перед полным итогом «Было / Стало»; смену прежнего
решения назови в «Тебе решить»; отказы по `prd.md`.
