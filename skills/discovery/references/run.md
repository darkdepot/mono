# Вход и повторный вход

Команды из продукта. `<папка>` = `$TMPDIR/mono-discovery/<короткое имя проекта>/`,
в продукт ничего не клади. Файлы пиши командой оболочки, не правкой файлов. `<конфиг>` = `.agents/mono-workflow.config.json`.

## Старый путь

Одобренный пакет прежнего Handoff (`mono:check discovery`, Old path), явной просьбы
о Discovery нет: ничего не пиши, дальше `mono:handoff`. Есть `mono-prd: approved`:
вход всегда.

## Задача этапа

Задача проекта с меткой `Этап`, название `Discovery: <проект>`. Открытая: работай;
закрытая: открой; отложенная без наступившего условия или возврата владельцем:
назови условие, стоп. Нет: создай по `<корень>/templates/stage-task.md`, исполнитель
владелец; нет метки: создай. Журнал и проверки входа в ней; отказ: причина, следующий
этап, закрытие задачи.

## Идея

Проект и все страницы комментариев сохрани сырыми ответами Linear в
`<папка>/linear/`: `project.json`, `comments-N.json`, `comments-N.request.json`
(`{}` сначала, `{"cursor":"<курсор прошлого ответа>"}` дальше). Не правь ответы.

```bash
node <корень>/scripts/idea-gate.mjs check --mode fresh --dump <папка>/linear --config <конфиг>
```

Решает код строки `idea-gate: <pass|fail>: <код>`, не exit. `pass`: дальше;
`stale` печатается как `fail`: дальше, в журнал «описание менялось после утверждения»;
`legacy-migrate`: дальше, «Зачем» из описания, в журнал «до записи Idea»;
`no-record`, `bad-record`, `other-project`: `mono:idea`; другое: стоп, назови код.

## Исследование

Документ по `mono-research` с `uuid` проекта, не названию. `outcome`: `ready`
(совет в «Кратко»), `hold` (фактов не хватило), `not-required` (мелочь).
Блок не читается, их несколько, исход вне набора или нет `reason` у `hold`/
`not-required`: стоп, `mono:research`. Несколько документов: спроси, какой действует,
ссылку в журнал и комментарий решений. Нет: `mono:research`, кроме пакета с последним
одобрением строго до `researchGate.since` (нет: `RESEARCH_GATE_DEFAULT_SINCE`
в `<корень>/scripts/idea-gate.mjs`; в журнал «до Research»).

## До первого сообщения

Прочитай идею с утверждением и решениями, Research целиком, данные и код сценария:
текущий путь, ограничения, готовые возможности. Факт ищи сам (`helpers.md`),
недоступное назови. Вопрос только об открытом выборе, меняющем результат;
ответ из источников или разговора используй, не спрашивай снова.

## Повторный вход

PRD по `document` последней `mono-prd: approved`, иначе среди документов проекта;
несколько: спроси. Правка владельца или ответ из Handoff: только затронутое,
без повторного выбора, «Было / Стало» и новое утверждение в том же касании;
из Handoff без финала, возврат ему. Вызов техлида отложить пункт: `prd.md`, без
новой карточки и открытия задачи. После перерыва продолжай по комментарию решений
и журналу без пересказа.
