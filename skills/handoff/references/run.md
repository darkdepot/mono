# Вход и повторный вход

`<конфиг>` = `.agents/mono-workflow.config.json` продукта; файлы только
в `$TMPDIR/mono-handoff/<короткое имя проекта>/`.

## Вход

`mono:check discovery` (`<корень>/skills/check/SKILL.md`) один раз до смены входов.
Отказ: стоп без записей, причина и маршрут: идея → `mono:idea`, Research →
`mono:research`, текущее утверждение PRD → `mono:discovery`.

Идея `fresh`: `pass` дальше. `stale`/`legacy-migrate`: автономный старт стоп;
оркестратор несёт идею владельцу в `mono:idea`, ждёт его согласия с показанным
и подтверждённой записи; до неё нет Research и работы. В сессии владельца
текущая идея идёт в итог и старт по `record.md`.

Входы: PRD по `document` последней `mono-prd: approved`, выбранное проверкой
«Исследование», Tech Spec и дизайн, если есть. Сначала `route` по `record.md`,
даже без PRD, затем нужные записи. Негодный Design → Design, неизвестный маршрут
→ `bad-record`; старый путь только после `pass`. Вопросы по «Кто что решает».

PRD без `next=`: существующую `mono-tech` проверь командой `tech` из `record.md`.
Действующая запись для текущего PRD (`pass`): потреби её Spec и продолжай без
предложения Tech Evaluation. Размер читай через соответствие в
`skills/discovery/references/prd.md`, без переоценки старого PRD; маршрут решает `next=`.
Нет годной записи и размер средний/большой: вопрос о старте Tech Evaluation
по `owner-dialog.md` с позицией и причиной. Согласие владельца (в делегированном —
оркестратора) открывает старый путь; без него нет пакета и продолжения.
Обсуждение не обходит техоценку; маршрутизатор и тест прежние.

До нарезки признак большего размера по правилам Discovery назови в итоге;
у небольшого также больше одной задачи или риск задачи deep/risky. Останови
нарезку, верни в Discovery на повторное утверждение PRD; нужный техлид до нарезки.
Понижение только при повторном утверждении PRD. После старта удержи объём,
иначе ремонт пакета; риск задачи — отдельная шкала.

## Старый путь и старый пакет

Старый пакет: одобрение прежним Handoff (`approval_status=approved`, строго до
`ideaGate.since`, допустимо без неё), без `mono-package: recorded`. Не заменяй,
не переводи и не пересобирай; правка только по `references/repair.md`.
Нет одобренного пакета и утверждения PRD → `mono:discovery`.

## Повторный вход

Текущая запись пакета последняя в цепочке по `previous`.
- Старта нет: проект в Ready, это разговор об итоге или правка до старта;
  повтори даже прежний итог с новым вопросом по `owner-dialog.md`.
- Старт есть: правка только ремонтом.
- Прервались записи: проверь Linear (запись, задачи проекта без метки `Этап`,
  статус), допиши недостающее без дублей. Продолжай по записи.

## Кто пишет

Сессия этапа сама пишет и читает каждую запись Linear обратно. Задачи: владелец
(`assignee: "me"`), до старта (`backlog` или `unstarted`). Проект только в Ready
после всех проверок; в Delivery переводит `mono:implement`.
