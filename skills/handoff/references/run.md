# Вход и повторный вход

`<конфиг>` = `.agents/mono-workflow.config.json` продукта; файлы клади
в `$TMPDIR/mono-handoff/<короткое имя проекта>/`, в продукт ничего не клади.

## Вход

`mono:check discovery` один раз (`<корень>/skills/check/SKILL.md`), до смены входов.
Отказ: стоп без записей, строка причины и маршрута: нет идеи в `mono:idea`,
исследования в `mono:research`, текущего утверждения PRD в `mono:discovery`.

Идея `fresh`: `pass` дальше. При `stale`/`legacy-migrate` автономный старт
делегированного проекта стоп: оркестратор несёт идею владельцу в `mono:idea`,
ждёт его кнопки и подтверждённой записи; Research и работа до неё не начинаются.
В сессии владельца текущая идея идёт в итог и запись старта по `record.md`.

Входы поимённо: PRD по `document` из последней записи `mono-prd: approved`;
«Исследование», выбранное проверкой; Tech Spec и дизайн, если есть: сверяешь
как входы. Всегда сначала `route` по `record.md`, и без PRD, затем
каждая нужная запись. Негодный Design — в Design, неизвестный маршрут —
`bad-record`. Послабления старого пути только после `pass`;
открытые вопросы по «Кто что решает».

PRD без `next=`: существующую `mono-tech` проверь командой `tech` из `record.md`.
Действующая запись для текущего PRD (`pass`): потреби её Spec и продолжай без
предложения Tech Evaluation. Нет годной записи и размер «обычное» или «проект»:
окно «Начать Tech Evaluation» / «Ещё обсудить». Согласие владельца (делегированный:
оркестратора) открывает старый путь. Без согласия не продолжай и пакет не пиши;
обсуждение не обходит техоценку. Маршрутизатор и его тест прежние.

## Старый путь и старый пакет

Старый пакет: одобрение прежним Handoff (`approval_status=approved`, строго до
`ideaGate.since` допустимо без неё), без `mono-package: recorded`. Новый пакет поверх не пишешь, не переводишь и не пересобираешь;
правка только по `references/repair.md`. Проект без одобренного пакета и без
утверждения PRD всегда идёт в `mono:discovery`.

## Повторный вход

Запись пакета есть: текущая версия последняя в цепочке по `previous`.
- Старта нет: проект в Ready, это разговор об итоге или правка до старта; покажи
  итог заново только если он изменился.
- Старт есть: правка только ремонтом.
- Работа прервалась на записях: посмотри, что уже в Linear (запись, задачи
  проекта без метки `Этап`, статус), допиши недостающее, ничего не дублируй.
После перерыва продолжай по записи пакета.

## Кто пишет

Сессия этапа сама пишет, кем бы ни была запущена. Каждую запись
в Linear читай обратно. Задачи: исполнитель владелец (`assignee: "me"`),
состояние до старта (`backlog` или `unstarted`). Статус проекта меняешь только
на Ready, после всех проверок; в Delivery переводит `mono:implement`.
