# Проверка черновика до записи

Черновик записи пакета и тел задач смотрят двое, до первой записи в Linear:
проверяющий и вторая модель другой семьи. Оба только читают и только сообщают.
Обязательно для `standard`, `deep` и `risky`; у `tiny` совет, пропуск с причиной
в заметках записи и в «Ревью-гейт» задачи.

## Проверяющий

`mono:review handoff` в режиме до записи: ему передаёшь черновик записи, тела
задач, ссылки на проект, PRD, «Исследование» и Tech Spec, если есть. Отсутствие
записи и задач в Linear для него норма.

## Вторая модель

Один проход, только чтение, в фоне, параллельно с проверяющим. Модель и усилие
роли по `<корень>/references/model-policy.md`. Из Claude Code роль `second-voice`:
`codex exec --ignore-user-config -m <модель> -c model_reasoning_effort=<усилие> -s read-only "<задание>" < /dev/null`;
из Codex роль `second-voice-alt`:
`claude -p --strict-mcp-config --model <модель> --effort <усилие> "<задание>" < /dev/null`, нужна сеть.
Для проверки пакета до записи оркестратор применяет свой протокол Second Voice,
лимит тот же. Вторая модель недоступна: у `standard`, `deep` и `risky` это стоп
до первой записи пакета и задач, владельцу одной строкой, что подключить; у `tiny`
пропуск советом с причиной в заметках.

Задание:

```text
Ты независимый тимлид. Вот проект, PRD, «Исследование», итог разведчика по коду,
черновик записи пакета и тела задач. Исполнитель видит только свою задачу.
1. Где исполнитель будет гадать: дыра, неоднозначность, неверная граница задачи.
2. Требование PRD без задачи, задача без требования, нарушение «Что не входит».
3. Нарезка: лишняя задача без причины too-big, shared-base или probe; общие места
   без цепочки; проба внешнего сервиса не первой.
4. Решение, которое меняет то, что видит или получает владелец, спрятано в «Решил сам».
5. Занижен риск; deep или risky без общих решений.
Коротко, по находке на строку, важное первым, без вступления.
```

## Диспозиция

Каждая находка обоих: исправлена в черновике или отклонена с причиной. После
правки, которая меняет решение, задачу или риск, ещё раунд; не больше трёх
раундов. Три раунда не разрешают запись: блокирующая находка после них остаётся
стопом, неблокирующие идут в диспозицию в заметках записи. Находка, которой
нужна правка PRD, идёт владельцу вопросом и в Discovery, как в сверке. Владельцу
про проверку не пишешь; одна строка, только если вторая модель против твоей
нарезки по сути и ты с ней не согласился.

Второй модели передавай тексты или локальные пути, не ссылки Linear: подключений владельца у неё нет.
