# Проверка черновика до записи

Черновик записи пакета и тел задач смотрят двое, до первой записи в Linear:
проверяющий и вторая модель другой семьи. Оба только читают и только сообщают.
Одна задача любого риска, включая `tiny`: оба обязательны, ровно один круг,
совета вместо ревью нет. Несколько задач: обязательно для `standard`, `deep`
и `risky`; у `tiny` совет, пропуск с причиной в заметках и «Ревью-гейт» задачи.

## Проверяющий

`mono:review handoff` в режиме до записи: ему передаёшь черновик записи, тела
задач, ссылки на проект, PRD, «Исследование» и Tech Spec, если есть. Отсутствие
записи и задач в Linear для него норма.

## Вторая модель

Один проход, только чтение, в фоне (в Codex на переднем плане с таймаутом команды
`600000`, жди итога, не прерывай), параллельно с проверяющим. Модель и усилие
роли по `<корень>/references/model-policy.md`. Из Claude Code роль `second-voice`:
`codex exec --ignore-user-config --disable apps -m <модель> -c model_reasoning_effort=<усилие> -s read-only "<задание>" < /dev/null`;
из Codex роль `second-voice-alt`:
`claude -p --strict-mcp-config --model <модель> --effort <усилие> "<задание>" < /dev/null`, нужна сеть.
Нет ответа или вызов сам вернул ошибку: повтори один раз («Execution error» после твоей остановки
не в счёт).
Для проверки пакета до записи оркестратор применяет свой протокол Second Voice,
лимит тот же. Вторая модель недоступна при обязательном ревью: стоп до записи,
владельцу одной строкой, что подключить. Только при нескольких задачах `tiny`
может пропустить совет с причиной в заметках.

Задание:

```text
Ты независимый тимлид. Вот проект, PRD, «Исследование», итог разведчика по коду,
черновик записи пакета, Tech Spec (если есть) и тела задач. Исполнитель получает
свою задачу и покрытые ею пункты U записи.
1. Где исполнитель будет гадать: дыра, неоднозначность, неверная граница задачи.
2. Требование PRD без задачи, задача без требования, нарушение «Что не входит».
3. Нарезка: лишняя задача без причины too-big, shared-base или probe; общие места
   без цепочки; проба внешнего сервиса не первой.
4. Решение, которое меняет то, что видит или получает владелец, спрятано в «Решил сам».
5. Занижен риск, `risky` не по списку строгого пути в record.md; deep или risky без общих решений.
6. Каждое решение Tech Spec, нужное задаче, есть в записи; не выполняемое
   названо в «Что не входит». Одна задача ссылается на U номерами, без пересказа.
Каждую находку сам отметь «по сути» или «по формулировке»; без отметки она по сути.
Коротко, по находке на строку, важное первым, без вступления. При одной задаче
это единственный полный круг, у любого риска. Блокирующую P0/P1 по сути после
правки перепроверь сам только по этой находке; отклонить её можно только
опровержением из источника, «так было раньше» не опровержение. Поправка по
формулировке не открывает новый круг.
```

## Диспозиция

Каждую находку отмечает нашедший: «по сути» или «по формулировке», без отметки
считай по сути. Одна задача: один полный круг обоих, у любой метки риска.
Формулировку исправь без нового круга. Блокирующую по сути (P0/P1) исправь и
верни автору на точечную перепроверку только этой находки, не всего пакета;
не снята — запись остановлена. Отклонение блокирующей только опровержением из
источника, доказывающим ошибку; «так было раньше» не довод. Остальные находки
исправь или отклони с причиной в заметках.

Несколько задач: прежний порядок — после правки решения, задачи или риска ещё
раунд, до трёх; tiny может пропустить совет с причиной. После предела блокирующая
остаётся стопом, неблокирующие — в диспозицию. Находка требует правки PRD:
вопрос владельцу и Discovery, как в сверке. Владельцу о проверке не пишешь,
кроме строки о несогласии второй модели с нарезкой по сути.

Второй модели передавай тексты или локальные пути, не ссылки Linear: подключений владельца у неё нет.
