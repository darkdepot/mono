# Когда этап ведёт оркестратор

Design ведёт сама сессия оркестратора после Discovery по `next=design`, не
воркер и не отдельная сессия дизайнера. Шаги, Paper, проверка по картинке,
неизменяемые PNG и команда проверки те же. Прочитай эту справку до первого
шага; она заменяет окна, выбор направления владельцем и финальный переход.

- Дизайнер сам выбирает направление по эталонам и правилам вкуса, с причиной.
  Все шаги фичи проходят последовательно, результат каждого проверяется по
  картинке до следующего. Отдельного выбора или утверждения владельца нет.
- Нет памяти продукта: передай владельцу один вопрос «на кого равняться»
  с предложенными сильными эталонами в два кольца и причиной у каждого.
  Этот проект ждёт ответа, остальные идут. Ответ подтверждает эталоны;
  молчание не согласие. Новые правила вкуса по-прежнему только с его согласия.
- Утверждай макет записью U2 `mono-design: approved` с `by=orchestrator` и
  строкой причины ниже, включая выбранное направление и опору на память.
  Правка PRD — Discovery в том же касании, тоже `by=orchestrator` с причиной,
  затем запись дизайна на новую версию PRD. Чужой PRD сам не правь.
- У оркестратора своих правил вкуса не записывай. Поздние комментарии владельца
  в Paper разбери при следующем запуске в продукте; правило только после согласия.
- Закончи задачу этапа, дай итог без окна и сразу начни Tech Evaluation или
  Handoff по `next=` записи дизайна. Их порядок задаёт цепь записей.
  Handoff покажет владельцу строку «Дизайнер решил за тебя:» рядом с техлидом.
  Idea и работу по-прежнему утверждает и начинает только владелец.
