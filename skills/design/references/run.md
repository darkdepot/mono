# Вход и задача этапа

`<конфиг>` = `.agents/mono-workflow.config.json` продукта,
`<папка>` = `$TMPDIR/mono-design/<проект>/`. Черновики вне репозитория продукта.

## Вход

Начало владельцем по кнопке или словам после Discovery; утверждение PRD само
этап не начинает. Передача в отдельную сессию: задание `<папка>/brief.md` содержит
ссылки на проект, PRD и Research, путь к памяти, размер задачи. Desktop открывает
её через `mcp__ccd_session__start_session`; Codex и терминал получают тот же файл
и строку команды для своего хоста: `/mono:design <путь к brief.md>` в Claude Code,
`$mono:design <путь к brief.md>` в Codex. Свежий контекст, не фоновый исполнитель. У оркестратора этап идёт в его
сессии по `orchestrator.md`, без отдельного запуска и окон.
Discovery не создаёт чужую задачу этапа.

1. `mono:check discovery` должен дать PASS на текущих входах. Нет: причина и
   адрес нужного этапа; результата Design нет.
2. Сохрани свежие ответы Linear как есть: `project.json`, все `comments-N.json`
   с `comments-N.request.json` ({} первой, дальше фактический предыдущий cursor),
   `prd.json`. Маршрут проверяй до выбора пропускаемых этапов:
   `node <корень>/scripts/idea-gate.mjs route --mode fresh --dump <папка>/linear --config <конфиг>`.
   Только exit 0, «Готово», JSON `pass`. `bad-record`: стоп к писавшему этапу,
   не отсутствие записи. В PRD нужны `design=needed next=design`.
3. Без `design=` старый путь Design по записи, а не дате: сессию не начинай.
   Просьба владельца о Design идёт через повторное утверждение PRD в Discovery;
   дизайнер не добавляет вторую пометку маршрута. `design=not-needed` тоже мимо
   Design, дальше `next=` PRD. Отдельной записи «дизайн не требуется» нет.
4. Прочитай утверждённый PRD, идею, выбранное исследование, прежние решения и
   комментарии дизайна. При повторном входе — прежнюю запись и её картинки.

## Задача этапа

Найди `Design: <проект>` по проекту, метке `Этап` и префиксу.
Открытую продолжай, закрытую на повторном входе открой; отложенную только по
условию возврата или слову владельца. Нет: создай по
`<корень>/templates/stage-task.md`, исполнитель владелец. Метки нет: создай.
Правила `<корень>/references/lifecycle.md`, «Задачи этапов» действуют целиком.
При отказе входа причина и куда дальше в своей задаче, затем Done; без записи
утверждения. Каждую запись читай обратно. Статус проекта не меняй, ветки, PR,
Tech Spec и задачи реализации не создавай.

Один комментарий решений: входы и версии; размер и его изменения; эталоны и
согласие; обновление экранов с прода; референсы с принципами; направления и
выбор; сценарии и состояния; проверка картинок до каждого показа; ветки Paper,
их три исхода и согласие; «Было / Стало» PRD; утверждение и запись с результатом
команды; ссылки на картинки, повторные замечания и что из них уже было правилом.
Продолжай после перерыва по нему. После успешной записи и проверки задача Done.
