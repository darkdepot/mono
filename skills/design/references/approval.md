# Утверждение, запись, повторный вход

Запись — комментарий проекта, а не документ и не вложение задачи.

## Вход для исправления записи

`route` вернул `bad-record` с `stage=mono:design`: войди только для замены своей
негодной записи. Сохрани исходный отказ; полный `mono:check discovery` остаётся
FAIL, его PASS для этого входа не требуется. Отдельно проверь входы Discovery:
утверждённые идею и выбранное Research, последнюю запись PRD, свежий документ
с совпадающими id/updatedAt и годные поля маршрута PRD. Повреждение, устаревание
или неизвестный писатель выше по цепи — стоп к владельцу; нехватка данных тоже
стоп. Вход исправления не добавляет Design в маршрут.

Негодная запись не доказывает прежнее утверждение макета. Восстанови точную
утверждённую версию по независимому подтверждению, включая Paper и PNG, либо
пройди обычную проверку картинок и новое утверждение по режиму. Старый комментарий
и PNG не переписывай, поля и хеш под несогласованные картинки не подгоняй.
После старта работы — Handoff/ремонт пакета или принятый дрейф Ship, а не тихая
замена входов.

Запиши новый результат по порядку ниже; на свежих сырых ответах повтори `route`,
`design` и полную проверку Discovery. Только их успешный результат завершает
исправление. До него нет выхода из этапа, Handoff, Ready или старта работы;
отказ другого писателя передай ему, не пропуская этап цепи.

## Правка PRD в том же касании

Макет нашёл расхождение: рядом «Было / Стало» ровно затронутого PRD. Одно окно
«Утвердить» / «Ещё обсудить» утверждает картинки и правку вместе. Ведёт владелец:
только кнопка на показанной версии; слова продолжают разговор. Design сам PRD
не меняет. После согласия вызови Discovery в том же касании: он меняет PRD,
читает обратно и пишет `mono-prd: approved` с `design=needed next=design`, затем
ты `mono-design` с новым `prd-updatedAt`. Контракт PRD и его отпечаток не меняются.
Записалась только первая: повтори вторую по тому же утверждению, не проси ещё
одно нажатие и не делай дубликат первой. Посторонняя правка после показа требует
нового утверждения.

## Снимок и запись

1. Утверждённые артборды скопируй `duplicate_nodes` на страницу Paper
   «Утверждено <ДД.ММ.ГГГГ>». `export` выгружает PNG по порядку показа:
   `NN-<название>.png`, только латиница, цифры и дефисы. Не меняй утверждённую
   страницу; новая версия в новой странице и папке.
2. Выгрузи в новую временную папку, посчитай `images` из неё:
   `LC_ALL=C ls *.png | LC_ALL=C sort | xargs shasum -a 256 | shasum -a 256`.
   Только имена файлов в UTF-8, запуск внутри папки. Перенеси целиком в
   `~/.mono-agent-workflow/design/<slug>/approved/<uuid проекта>/<первые 12 знаков images>/`.
   Прошлые версии не перезаписывай; существующая папка допустима только с точно
   теми же файлами и пересчитанным хешем. Считай хеш ещё раз из конечной папки.
3. Перечитай PRD и последнюю запись его утверждения: id и `updatedAt` совпадают.
   Новый PRD без согласованной правки — новый круг, не подмена поля под старый показ.
4. Комментарий проекта, первая строка в заборе `text`, только ключи без пробелов
   внутри значений; ниже список PNG, ссылка на согласие и причина повторного входа:

```text
mono-design: approved project=<uuid> prd=<uuid PRD> prd-updatedAt=<ISO> paper=<ссылка> images=<sha256> next=tech-evaluation|handoff by=owner|orchestrator
```

`next=` по «Размер» утверждённого PRD: «обычное» и «проект» → `tech-evaluation`,
«мелочь» → `handoff`. Глубина работы дизайнера это поле не меняет. Действует
последняя запись по `createdAt`; повреждённую новую нельзя заменить старой.
Отдельной записи «дизайн не требуется» нет.

5. Прочитай комментарий обратно байт в байт. Сохрани все свежие ответы Linear
   без переделки: `project.json`, `comments-N.json`, `comments-N.request.json`,
   `prd.json`. Запусти `node <корень>/scripts/idea-gate.mjs design --mode fresh --dump <папка>/linear --config <конфиг>`.
   Только exit 0, «Готово», JSON `pass`, затем `mono:check design` PASS завершают
   запись. `no-record`, `stale-prd`, `stale-images`, `bad-record` — стоп с причиной;
   чтение вместо команды не годится. Годность: PRD соответствует последнему
   утверждению, папка версии есть, `images` пересчитан и совпал.

## Повторный вход

До старта: дизайнер сверяет новый PRD, предыдущие картинки и комментарии Paper.
Маршрут тот же, экраны не меняются: сам зафиксируй причину, новая запись с новым
`prd-updatedAt` и теми же `paper` и `images`, без показа. В журнале прежнее
утверждение и вызвавший этап. Не меняй прежние PNG. Экраны меняются: новый круг
с показом и утверждением. Сменился маршрут PRD: записи этапов ниже не действуют,
этапы проходят заново с показом по режиму, исключение неизменённых экранов не
применяй. После старта — ремонт пакета, не тихое обновление записи.

Tech Evaluation вернул технически неподходящий макет или «предлагаю убрать:
…, потому что …» о пункте на утверждённых экранах: новый круг, правка PRD через
Discovery в том же касании, затем новая запись и возврат к техлиду. Пункт не на
экранах отложен на утверждённой странице техлида: Discovery меняет только его;
при неизменных экранах новая запись с теми же картинками и новым `prd-updatedAt`
без показа, затем Tech Spec и `mono-tech` с id этой записи в `design=`.

## Финал

Закончи журнал, закрой `Design: <проект>`. Отдельно: что утверждено, ссылка на
Paper и запись, какие сценарии и состояния проверены по картинке, что осталось
непроверенным, какие правила записаны с согласия. Затем окно по `next=` своей
записи: «Начать Tech Evaluation» или «Начать Handoff», второе «Ещё обсудить».
В режиме владельца сам следующий этап не начинай; его явные слова тоже старт.
У оркестратора после записи сам начни следующий этап цепи по `orchestrator.md`.
