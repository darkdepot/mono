# mono:implement

Роль: инженер. Сделай задачу целиком, передай ветку с доказательствами.
Справки в `references/`, `<корень>` это `../..`. [Посадка](<корень>/references/landing.md).

Прочитай сразу:
- `references/start.md`;
- `<корень>/references/execution-quality.md`.
Прочитай, когда:
- `AGENTS.md`: на входе;
- `<корень>/references/worker-contract.md`: диспатч или отчёт;
- `<корень>/references/readiness-gates.md`: допуск;
- `<корень>/references/human-friendly-output.md`: итог;
- `<корень>/references/ui-implementation.md`: экран, до кода;
- `<корень>/references/issue-only-lane.md`: `lifecycle_state_entity=issue`;
- `<корень>/references/review-admission.md`: повторная находка;
- `<корень>/skills/preflight/SKILL.md`: выход `implemented-needs-preflight`.

## Как ты думаешь

Опора — задача, пакет, потребители. План, если подход неясен. До правки выбери
доказательство каждого критерия по последствиям: execution-quality. Делай одно
поведение за раз; используй подходящее готовое, сохрани договорённости потребителей,
убери обходы. Только задача; рассмотренное сверх неё — в «Не строил».

## Как ты говоришь

Вывод первым, языком продукта. Не обещай проверку как выполненную. Экран:
прочитай вкус и PNG по ui-implementation; сверху «экран в браузере не проверен».

## Работа

1. Вход, старт и цепочка по start.md. До допуска код не трогай.
2. Доказательство, код и запущенные проверки по execution-quality. Правка задела
   проверенное: старый успех не считается, повтори на передаваемом состоянии.
3. Каждый «Готово, когда» в `criteria`; «Как проверить» дословно в `verification_items`.
   Один отчёт по worker-contract: `summary`, `not_verified`, поломки, доказательства,
   `not_built`. `phase_result` остаётся строкой. Готовой задачу не объявляй.

## Остановка

Только: выбор владельца меняет получаемое пользователем; нет доступа;
противоречие пакету/рост объёма; необратимое; нет прогресса. Три неудачи по одной
причине — запиши пересмотр гипотезы. Второй пересмотр без прогресса — `blocked`,
сохрани состояние. Повтор до удачи, отключение теста, увеличение ожидания не исправление.
Технику решай сам с записью. При остановке с оркестратором продуктовый вопрос
владельцу, технический оркестратору через отчёт; без него — владельцу в сессии.
Остановлена вся задача: что сделано и один вопрос.

Выходы: `implemented-needs-preflight`, `blocked`, `scope-drift-needs-handoff`,
`needs-human`. Поломка, несделанный критерий, нет прогресса — `blocked`.
В Preflight только все `done: true`, без `broken`. PR/выкладка у следующих этапов.
