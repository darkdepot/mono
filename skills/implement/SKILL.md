## Как ты думаешь

Задача/пакет/потребители, план при неясности. Поломка вне критериев:
не мешает — `not_built` с причиной; мешает критерию/«Как проверить» — стоп по U5:
проект `scope-drift-needs-handoff`, без проекта `needs-human`, расширение только
через mono:issue. Запись решения остановку не заменяет.

## Как ты говоришь

не доказательство. Сверху «экран в браузере не проверен».

## Работа

1. Вход/старт/цепочка — start.md, код после допуска.
2. До первой правки текстовой мелочи запиши в доказательства «поведение не меняется» и причину.
   Фраза запрещена в остальных отчётах.
   Доказательство/код/проверки по execution-quality. Правка задела
   проверенное: повтори на передаваемом состоянии. `confirmed` — команда с кодом 0
   на записанных `head`/отпечатке после последней правки; подтест упавшего запуска
   не подтверждает, узкий запуск допустим. Отпечаток только помощником
   worker-contract, команда в доказательстве критерия.
3. Все «Готово, когда» в `criteria`, «Как проверить» дословно в `verification_items`.
   Отчёт по worker-contract, `phase_result` строка.

## Остановка

Только: выбор владельца меняет результат; нет доступа; противоречие пакету/рост
объёма; необратимое; нет прогресса. Три неудачи одной причины — пересмотр гипотезы
с записью, второй без прогресса — `blocked`, состояние сохранено. Повтор до удачи,
отключение теста, рост ожидания не исправление. Технику решай/запиши сам. Стоп всей
задачи: сделанное и один вопрос; с оркестратором продуктовый владельцу, технический
оркестратору через отчёт, иначе владельцу в сессии.

Выходы: `implemented-needs-preflight`, `blocked`, `scope-drift-needs-handoff`,
`needs-human`. В Preflight все `done: true`, без `broken`; иначе `blocked`.
Готовой не объявляй; PR/выкладка дальше.
