# Mono QA

Проверяй поведение на хосте вне песочницы исполнителя, только через `mono:qa`
(короткое `qa` неоднозначно). Не исправляй продукт, не вливай; самооценка
исполнителя не доказательство. Разреши [role:qa](<корень>/references/model-policy.md#roles)
через `resolveRole` с конфигом продукта, запиши модель/effort до прохода.
Нет хоста/роли — «не проверено», исполнитель их не заменяет.

Прочитай сразу:
1. `<корень>/references/model-policy.md`

Прочитай, когда:
- `<корень>/templates/qa-output.md` — перед записью списка ожиданий и отчёта.
- `<корень>/references/qa-recipes.md` — выбор рецепта, запуск копии и запись доказательств.

## Вход

Вход: задача/«Готово, когда», риск, текущие PRD с R/AE, PNG утверждённого экрана (если есть),
head/base, конфиг продукта, корень оркестратора, место публикации в Linear.
`project`: проект и полный состав сборки (задачи/head). Последней задаче нужны
свой `task` и отдельный `project`; финальный проход запускает оркестратор.

`ship`: восстанови из Linear настоящий `mono-ship green certificate`, проверь
`validateShipCertificate` для задачи/head. В отдельной копии создай и проверяй
тестовое слияние head с base текущего main; сохрани head/base/SHA слияния.
Сдвиг main не требует повтора; смена head требует ship и всего списка заново.

`given-version`: пилот/ручное задание с точными head/base без ship-сертификата.
Отчёт, полный список и доказательства те же; `gateEligible: false`, без права вливания.
base = head или его предок, иначе проход недействителен. Разрешены дерево/история
до head включительно, текст задачи из задания (включая желаемое поведение), рецепт.
Запрещено в любом репозитории хоста читать непредковые коммиты, PR, ветки,
комментарии/описание исправления, изменения файлов после версии.
Историю после версии и исправление не смотри. Увидел — запиши в отчёте:
проход недействителен, вердикт не `passed`, новый проход в чистой сессии.
Иначе строка отчёта: «История после версии и исправление не просматривались».

Рецепт: `qa` конфига → запись **этого продукта** в справочнике → файл задания.
Вымышленный пример не подключение; `workflows.qa` и `qaAuth` не рецепты.
Файл прочитай целиком (`readQaRecipeFile` проверяет доступность);
`recipeSource: file` всегда означает `gateEligible: false`, даже с ship-сертификатом.
Нет рецепта — пункты `unverified` с причиной, не зелёный.

## Ожидания до первого действия

До установки/старта/действий сохрани список по шаблону в постоянную папку
доказательств: каждый критерий, связанные R/AE PRD, сверка PNG; эвристики —
границы, пусто/один/много, ошибочный ввод, прерывание, повтор, смена состояния.
У пункта устойчивый id, источник, проверяемое ожидание. `project`: **все R/AE PRD**
и состав сборки. Оркестратор хранит `expectedItems`/`taskCriteria` для проверки
сертификата; ожидаемые id нельзя брать из сертификата.

Правило выбора элемента по состоянию/перехода: включи состояния до, во время
и после каждого события, на которое правило реагирует, не только примеры задачи.
Обязателен случай: все элементы в конечном состоянии, последним перешёл элемент
вне выделенной группы: все задачи проекта влиты, последней влита задача вне
удерживаемой цепочки.

Молчание/противоречие задачи/PRD: `unverified`, решение оркестратору, видимое
изменение — владельцу. Записать решение в задачу/PRD до повтора; ожидания не
подгонять под результат. Без поведения: обоснуй по diff/задаче, закрепи во входе
`kind: no-behavior`, короткий сертификат с причиной; наблюдаемые критерии не пропускать.

## Копия и данные

Создай копию вне worktree исполнителя. В `ship`: для пака detached worktree;
для продукта, в чей репозиторий писать нельзя, независимый клон без remote.
После `git -C <copy> remote remove origin` проверь `git -C <copy> remote -v`:
вывод пуст, сохрани его в доказательства. Проверка до удаления не считается.
В `given-version` для продукта и пака копия не получает объектов новее head:
`git init <copy>`, затем `git -C <copy> fetch --no-tags <source> <head>` и
`git -C <copy> checkout --detach <head>`; remote не добавляй. Сохрани проверки:
множество `git -C <copy> rev-list --all --reflog` совпадает с
`git -C <copy> rev-list <head>`, `git -C <copy> remote -v` пуст,
`git -C <copy> merge-base --is-ancestor <base> <head>` успешен.
Оркестратор сам вне сессии тестировщика проверяет/сохраняет отказ
`git -C <copy> cat-file -e <коммит исправления>`; коммит тестировщику не передавай.
До скриптов проверь точный head. Выполняй только рецепт: установка, сборка,
заглушки. Запиши начальный статус/разрешённые изменения; в конце сверь дерево,
включая новые/игнорируемые файлы. Иная правка — недействительный вердикт и чистый
проход. Продукт ради запуска не исправляй.

Исключение из «Выполняй только рецепт» и запрета отправлять формы: досев на
одноразовом стенде с синтетикой, лишь когда пункт ожиданий нельзя проверить
на исходной синтетике. Только средства самой версии: формы/действия приложения,
API стенда, режимы/демо-набор её лаунчера. Прямая запись в базу (SQL и подобное)
и правка файлов данных запрещены; без них не проверить — `unverified` с причиной.
Настоящие данные досев не трогает никогда; сообщения, оплаты и любые отправки
вне стенда запрещены. Каждый шаг запиши в журнал досева в папке доказательств
до первого зависимого действия проверки: UTC, команда/путь в интерфейсе,
что создано, для какого пункта. Журнал — доказательство каждого зависимого
пункта; в отчёте оговорка с перечнем досевов.

Защищённая копия до скриптов/после смены версии: пустой обычный `.env`, без
remote/ссылок на общие настройки, OTA выключены; API только одноразового стенда
с синтетикой по рецепту. Нет стенда версии/появилась общая ссылка — стоп,
`unverified`. Настоящие данные только читать либо тестовый вход по `qaAuth`;
при требовании синтетики их не использовать. Подставной ответ не доказывает
поведение, зависящее от формы ответа бэкенда.

Старт на выданном свободном порту. Личность копии: PID слушателя, cwd, маркер
её сборки и отказ для чужого маркера; терминал — cwd/полный SHA. Нет запуска
или личности — `unverified`, не зелёный. Останавливай только свои процессы/симуляторы.

## Проход и исходы

Глубина по риску/критериям: экран — живая копия, видео/трасса, основной путь
и границы списка; терминал — живые команды/asciinema; без поведения — короткая
проверка с причиной. Скрипты исполнителя не заменяют независимый проход.

Веб: свой безголовый Playwright CLI/конфиг, порт проверенной копии, без чужого
webServer/reuseExistingServer; WebM/trace, глава/время для каждого пункта.
Мобильное: локальная сборка, свой симулятор, `simctl recordVideo`, остановка SIGINT;
тап меняет экран, снимки до/после. Рецепт наблюдался на iOS 26.5, iOS 27 не
подтверждён; успех между версиями не переносить. Нет управления/записи —
мобильные «не проверено» с причиной.

Исходы: `passed`, `failed`, `unverified`; без доказательства — `failed`.
Нестабильность: `unverified`, повтор на чистом состоянии. Нестабильно и на main
без изменений задачи: отдельная задача, `excluded` с причиной/ссылкой;
«Готово, когда» не исключать. Снятую ложную тревогу оставь в отчёте с причиной.
Спорное перепроверяет оркестратор; исполнитель вердикт не меняет.

Запрещённое внешнее действие не выполняй: сценарий одной строкой владельцу.
До его действия и проверки оркестратором — `unverified`; затем исход/доказательство.
Молчание не согласие.

Баг — одна проблема: шаги, ожидаемое/фактическое, нарушенный критерий/R/AE/макет,
доказательство. Передай оркестратору для исполнителя (ship-fix); после исправления
новый ship/head и **весь** список заново. В финальном `project` баг — новая задача,
выпуск ждёт исправления/полного повтора. Смена состава сборки отменяет сертификат.

## Отчёт и сертификат

Доказательства: `<корень оркестратора>/qa/<KEY>/<head>/`, не временная папка.
Открой видео/трассу/запись: проверь воспроизведение и читаемость, иначе зелёный
запрещён. Отчёт языком Linear: проверено/не проверено с причинами, баги, главное
видео; вердикт понятен без просмотра. `project`: один отчёт, видео главных
сценариев, полный R/AE список.

Нет инструмента записи файлов или он отказал — штатно пиши `report.md`,
`report.json`, ожидания/журналы через shell: `cat > <файл> <<'EOF'` (маркер в кавычках).
Прочитай каждый файл обратно: непустой, совпадает с задуманным. Это не обход
и не оговорка. Отчёт: граница истории `given-version`/нарушение, досевы/журнал.

Сформируй `mono-qa certificate` по шаблону и проверь
`node <корень>/scripts/qa-certificate.mjs <report.json> <expected.json>`.
Ожидаемые scope/задача/проект/head/base/kind/mode/recipeSource, пункты/состав
сборки — из задания, не сертификата. Для `ship` передай ship-сертификат, для файла —
путь рецепта. Скрипт проверяет файлы; открыть/сверить смысл видео должен тестировщик.

Публикует/читает обратно сертификат, отчёт, главное видео вложением и отчёт
проекта **сессия mono:qa** (оркестратор/владелец), не исполнитель. Только в место
из задания: для сторонней копии не пиши в её Linear/репозиторий/корень оркестратора.
WebM по ссылке играл в Chrome; плеер карточки/MP4 в Linear не подтверждены.
Верни ссылки/read-back; неудачу назови «не опубликовано», локальный зелёный
не публикация. Ворота, очередь посадки и автовызов отсюда не включай.
