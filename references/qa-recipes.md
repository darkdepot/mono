# Рецепты QA: копия, запись и загрузка

Наблюдения пробы на хосте 28.10.2026. Это рецепты запуска и сбора
доказательств, а не скилл, сертификат или включение ворот. Пробу здесь повторно
не запускали. Веб и мобильное показаны на вымышленном продукте **Example Ledger**:
его имена, пути, идентификаторы и команды стенда ниже — нейтральные замены
частного продукта пробы. Они не означают подключение этого продукта к воротам.
Рецепт терминального пака Mono приведён полностью.

## Общие условия

- Режим: `web`, `terminal` или `mobile`. Выполнять на хосте, где доступны
  браузер, локальные порты и симулятор, вне песочницы исполнителя.
- Доказательства хранить в `<корень оркестратора>/qa/<KEY>/<head>/`, не во
  временной папке: видео, трассу, запись терминала, снимки, логи запуска и
  подтверждения личности копии. `<head>` — проверяемая версия; примерные имена
  файлов ниже относительны к этой папке. Сохранять время шагов в UTC (`date -u`).
- Не отправлять сообщения и формы, не оплачивать, не менять настоящие данные.
  Навигация и чтение синтетических данных разрешены. Нет рецепта, безопасного
  источника данных или готовой копии — пункты «не проверено», вердикт не зелёный.
- Подставные ответы не доказывают поведение, зависящее от формы ответа
  бэкенда. Проба веба и мобильного использовала только одноразовый стенд с
  синтетическими данными и настоящими миграциями, не настоящий бэкенд.
- Успех записи ещё не доказывает поведение: файл должен открываться, действие
  должно быть видно. Нестабильный пункт — «не проверено» и повтор на чистом
  состоянии; нестабильность вне задачи получает отдельную задачу.

## web: независимая копия и синтетические данные

### Установка и старт

1. Создать независимый клон, а не worktree репозитория, в который нельзя писать:

   ```bash
   git clone --no-hardlinks <source-repository> <copy>
   git -C <copy> remote remove origin
   git -C <copy> checkout --detach <head>
   git -C <copy> rev-parse HEAD > <evidence>/checked-head.txt
   ```

   До установки зависимостей полный SHA должен совпасть с запрошенным `<head>`;
   при несовпадении остановить проход, пункты «не проверено». PID, cwd и маркер
   сборки ниже подтверждают сервер этой копии, но не заменяют привязку к коммиту.

   В пробе основной checkout и его `.git` не менялись, статус до и после
   совпал. Удаление remote защищает от случайного push из копии.
2. **До первого скрипта** создать пустой обычный `.env` внутри копии. В
   проверенном продукте скрипты build/dev иначе создавали симлинк на общие
   настройки с настоящим адресом базы. После каждой смены версии снова
   проверить пустую заглушку, отсутствие remote и ссылок на общие настройки.
   Если в версии нет безопасного стенда или появилась такая ссылка — остановить
   проход, пункты «не проверено».
3. Из корня копии установить зависимости и собрать веб:

   ```bash
   pnpm install --frozen-lockfile
   NEXT_TELEMETRY_DISABLED=1 pnpm build
   ```

   Проба использовала pnpm 10 с кешем. Пропущенные install-скрипты нескольких
   пакетов не помешали этому проходу; это не общее разрешение игнорировать их.
4. Получить свободный loopback-порт через временный listener на порту `0`,
   записать выданный номер и закрыть listener. Порт проверяется снова при старте:
   освобождение номера само по себе не гарантирует, что его никто не занял.
5. Запустить одноразовый стенд из корня копии. Условный путь Example Ledger:

   ```bash
   node qa/stand.mjs --investment-subledger --port=<port>
   ```

   В пробе лаунчер создавал свой контейнер `postgres:17` на случайном
   loopback-порту, накатывал настоящие миграции, сеял синтетику и запускал
   `next start --hostname 127.0.0.1 --port <port>`. Он передавал узкий набор
   переменных; runtime-guard запрещал чтение dotenv и внешние обращения.
   Обёртка `.sh` зашивала другой порт, поэтому вызывался `.mjs` напрямую.
   Это свойство проверенного стенда; у другого продукта такой лаунчер сначала
   должен существовать и обеспечивать те же ограничения.

### Готовность: отвечает именно эта копия

Строка `READY` с ожидаемыми итогами синтетики появилась за 56–64 с.
Она подтверждает запуск, но не заменяет проверку личности сервера:

```bash
lsof -nP -iTCP:<port> -sTCP:LISTEN
lsof -a -p <listener-pid> -d cwd
```

PID слушателя должен принадлежать запущенному серверу, его cwd — корню копии.
В пробе это был Next.js 16.2.9. Считать `.next/BUILD_ID` **этой сборки** и
проверить HTTP-маркер без правки кода:

- `GET /_next/static/<BUILD_ID>/_buildManifest.js` → `200`;
- тот же путь с чужим идентификатором сборки → `404`.

Совместно PID, cwd и уникальный маркер отличают копию от чужого сервера на
порту. Сохранить вывод и статусы в `web-identity-proof.txt`; отдельно проверить
свой контейнер через `docker ps --filter name=<stand-container-prefix>`.

Источником данных служит только синтетика стенда: условные счета и операции,
ожидаемые итоги в `READY`. Настоящий бэкенд был за Cloudflare Access: вебу нужен
вход владельца, мобильному — отдельная пара service token. Проба не входила,
настоящие данные не читала и не меняла. Наличие отдельного `qaAuth` не выясняли:
проверка настоящего доступа остановилась раньше, на входе владельца.

### Видео и трасса Playwright CLI

Использовать свой QA-конфиг вне штатного `playwright.config.ts`, отдельный
безголовый браузер и уже запущенную проверенную копию. Не наследовать штатные
`webServer`, `reuseExistingServer`, проекты или переменные запуска другого
сервера. Наблюдённые настройки собственного конфига:

| Настройка | Значение |
|---|---|
| `baseURL` | `http://127.0.0.1:<port>` |
| `webServer` | отсутствует |
| `video` | `{ mode: "on", size: { width: 1280, height: 800 } }` |
| `trace` | `"on"` |
| `screenshot` | `"on"` |
| `outputDir` | папка доказательств для этой версии |

```bash
QA_PORT=<port> QA_OUTPUT_DIR=<evidence>/playwright npx playwright test --config qa-probe/playwright.qa.config.ts
```

Наблюдённый сценарий: открыть главную (редирект на счета), операции и отчёт
денежного потока, без кнопок записи. Проход занял 7 с, 1 из 1. Получены
`video.webm` (VP8, 1280×800, 4,76 с, 272 599 байт) и `trace.zip` (125 файлов).
Для дальнейшего отчёта привязывать главы видео/трассы к проверяемым пунктам.

Открываемость проверили извлечением кадров встроенным ffmpeg Playwright;
`unzip -l trace.zip` показал `test.trace`, `0-trace.trace`, `0-trace.network`.
У этого ffmpeg только мультиплексоры `image2` и `webm`: `-f null` и MP4
недоступны, ffprobe не поставляется. Нельзя считать ошибку такого инструмента
ошибкой видео.

Первая попытка упала из-за селектора: первый найденный элемент был скрыт,
потребовался `filter({ visible: true })`. Во второй браузер поймал
`Minified React error #419`, в третьей ошибки не было. Это наблюдение
«нестабильно, не проверено», а не установленный баг продукта.

Остановка стенда: `kill -INT <launcher-pid>`. Проверенный лаунчер сам удалил
контейнер и хранилище; после остановки контейнера не было, порт был свободен.
Останавливать только свои процессы по сохранённым PID.

## terminal: полный рецепт пака Mono

<!-- mono-qa product: Mono Agent Workflow -->

Источник — проверяемая версия пака, данные — его локальные скрипты и fixtures.
Сеть, настоящий продукт и порт серверу не нужны. Создать detached worktree,
сохранив основной checkout и его ветку:

```bash
git -C <pack-repository> worktree add --detach <qa-copy> <sha>
brew install asciinema
cd <qa-copy>
asciinema rec --headless --overwrite \
  -c "bash -c 'echo worktree=\$PWD; git rev-parse --short HEAD; node scripts/read-budget.mjs | tail -15; echo exit=\$?'" \
  <evidence>/mono-pack-session.cast
```

Это запись живого выполнения, не склейка подготовленного вывода. `--headless`
работает без TTY; asciinema 3.2.1 создала asciicast v3: JSON-заголовок, события
`o`, завершающее `x` с кодом `0`. В записи были cwd копии, её head и
`Read budget: 99770 bytes / ~24942.5 tokens; 25 files; ceiling 99882 bytes; PASS`.
Это исторический замер пробы, не требуемое значение будущей версии.
Выведенный `exit` после конвейера относится к его последней команде; полную
проверку пака выполнять отдельно и сохранять её настоящий код выхода:

```bash
node scripts/verify.mjs
```

На копии пробы она завершилась зелёной, rc=0, за 2317 с на нагруженном хосте.
Не запускать команды публикации, изменения Linear или настоящих данных.

Проверить воспроизведение и получить текст:

```bash
script -q <evidence>/mono-playback.typescript asciinema play <evidence>/mono-pack-session.cast
asciinema convert --overwrite <evidence>/mono-pack-session.cast <evidence>/mono-pack-session.txt
```

Прямой `asciinema play -i 0.01 file.cast` без TTY падал с
`Device not configured (os error 6)`. Через `script` запись проигралась целиком:
20 строк, включая `PASS`, `exit=0`, затем `::: Playback ended`.
Считать файл typescript: если вывод `script` пустить трубой в инструмент агента,
часть теряется. `convert` дал чистый текст; `asciinema cat` в версии 3 склеивает
минимум две записи и для одной не подходит. После сохранения доказательств
удалить только созданный worktree: `git -C <pack-repository> worktree remove <qa-copy>`.

## mobile: локальная Release-сборка и управление

Использовать независимый клон с защитой настроек из `web`, тот же одноразовый
стенд и его синтетику. Настоящие данные и облачные сборки не использовать:
ни EAS, ни CI, ни TestFlight. Release содержит JS-бандл, Metro и порт 8081 не
нужны; порт API — выданный порт проверенного стенда.

1. Из `apps/mobile` копии выполнить:

   ```bash
   EXPO_NO_TELEMETRY=1 CI=1 npx expo prebuild --platform ios --no-install
   ```

   `ios/` создаётся только в копии. Затем отключить OTA в её Expo.plist,
   используя условное имя ExampleLedger:

   ```bash
   plutil -replace EXUpdatesEnabled -bool NO ios/ExampleLedger/Supporting/Expo.plist
   plutil -replace EXUpdatesCheckOnLaunch -string NEVER ios/ExampleLedger/Supporting/Expo.plist
   ```

   Проверять отключение после каждой смены версии. Без него Release может
   обратиться в EAS Update.
2. В `ios/` выполнить `LANG=en_US.UTF-8 pod install`. Без UTF-8 локали
   CocoaPods 1.17 на Ruby 4.0 падал с `Encoding::CompatibilityError`.
3. Создать отдельный симулятор, не использовать симулятор владельца:

   ```bash
   xcrun simctl create "Mono QA Example iPhone 17 iOS26" "iPhone 17" com.apple.CoreSimulator.SimRuntime.iOS-26-5
   xcrun simctl boot <udid>
   ```

4. Из `ios/` собрать, указав API только на стенд и DerivedData вне репозитория:

   ```bash
   LANG=en_US.UTF-8 EXPO_NO_TELEMETRY=1 EXPO_PUBLIC_API_URL=http://127.0.0.1:<port> xcodebuild -workspace ExampleLedger.xcworkspace -scheme ExampleLedger -configuration Release -destination "platform=iOS Simulator,id=<udid>" -derivedDataPath <derived-data> build
   xcrun simctl install <udid> <built-app>
   xcrun simctl launch <udid> com.example.ledger
   ```

   В пробе `BUILD SUCCEEDED`, подпись симулятору не понадобилась. Проверенный
   клиент не отправлял пару доступа на loopback (только на свой настоящий
   HTTPS-хост); это свойство клиента нужно проверять, не переносить на другие
   приложения по умолчанию. Готовность: API уже подтвердил PID/cwd/маркер из
   `web`, приложение запускается на своём симуляторе и показывает синтетику.

### Видео, тапы и исход R10

```bash
xcrun simctl io <udid> recordVideo --codec h264 --force <evidence>/mobile-sim.mp4
```

Запустить запись отдельным процессом с сохранением PID. Тапы делались
инструментом iOS Simulator сессии Claude Code (`tap` по координатам устройства):
вкладка операций сменила экран счетов, затем вкладка денежного потока открыла
свой экран. Переходы подтверждены отдельными снимками до и после тапов.
Одна запись или тап без видимой смены экрана этого не доказывает.

Остановить **SIGINT**: `kill -INT <recording-pid>`, дождаться завершения
«Recording completed. Writing to disk.». Полученный MP4: H.264, 61 с,
1206×2622, 990 610 байт. Через AVFoundation (Swift) извлечены кадры на
3,1 / 30,6 / 58,1 с; встроенный ffmpeg Playwright MP4 не читает.
После прохода выключить и удалить только свой симулятор, убрать свою копию и
DerivedData, сохранив доказательства в постоянной папке.

R10: сборка, видео и тапы подтверждены **на iOS 26.5**. На iOS 27.0 приложение
сразу падало с `EXC_BREAKPOINT`: UIKit сообщал
`Application failed to launch: UIScene life cycle is required for apps built with this SDK`.
SDK iOS 27 из Xcode 27.1 требует UIScene, а AppDelegate шаблона Expo SDK 57
его не принимает. Та же сборка запускается на iOS 26.5. Для iOS 27 нужна правка
продукта (UIScene или новый Expo); проба её не делала. Успех на 26.5 не
доказывает поддержку всех симуляторов 26.x или 27.

Отдельное наблюдение **без сверки**: итоги на мобильном — €2 555,70 и
€1 050,70 для инвестиционного счёта; строка `READY` ожидает €2 575,70 и
€1 070,70 для веба. README стенда называет строгий отказ мобильного контракта
намеренным. Это не разрешённое расхождение и не доказанный баг: сверка остаётся
у оркестратора, пункт «не проверено».

idb на хосте отсутствовал. XCUITest (`xcodebuild test -only-testing:`) назван
возможным переносимым вариантом, но проба его не проверяла и готовые UI-тесты
продукта не искала.

## Linear: что проверено при загрузке

Проба сделала одну разрешённую запись в задачу Mono: главное WebM-видео
вложением. Последовательность:

1. `prepare_attachment_upload` для `video.webm`, MIME `video/webm`.
2. `curl -X PUT --data-binary @file` со всеми подписанными заголовками дословно:
   HTTP `200`, около 1 с; подписанная ссылка жила 60 с.
3. `create_attachment_from_upload`, затем `get_issue` для обратного чтения.
4. Скачать вложение: SHA-256 совпал с исходным файлом. Заголовки:
   `content-type: video/webm`, `content-disposition: inline`, `accept-ranges: bytes`.
5. Открыть задачу: в Resources строка-ссылка, элемента `<video>` нет. По клику
   видео играет в Chrome: `currentTime` меняется, 1280×800, 4,76 с.

На файле 272 599 байт ограничения размера не встретили; инструмент заявлял
лимит 2 ГБ, но загрузку такого размера не проверяли. Это доказательство
открываемости WebM **по ссылке**, не встроенного плеера в карточке. MP4 мобильной
записи и вставка через `prepare_file_upload` в Markdown комментария/описания
не проверялись. Проигрывание в Safari также не подтверждено.
Повторная загрузка — внешняя запись, ей нужно отдельное разрешение; рецепт
сам по себе его не даёт. Подписанные URL и заголовки не публиковать в репозитории.

## Хост и длительность шагов

Наблюдённый хост: macOS, Xcode 27.1, Node 26.5, OrbStack Docker 29.8.
Нужны Git, pnpm 10, Python 3, Docker с `postgres:17`, `pg_isready`/`psql`
(libpq), Xcode с рантаймом iOS 26.5, CocoaPods с UTF-8 локалью, asciinema 3
и инструмент управления симулятором. Playwright 1.61.1 использовал кеш
Chromium 1228 и ffmpeg 1011. Системные ffmpeg/ffprobe и idb не понадобились;
MP4 проверяли через AVFoundation.

Времена из отчёта, не норматив: зависимости были в кеше, хост одновременно
собирал приложения. Там, где длительность не измерена отдельно, число не
додумывается.
