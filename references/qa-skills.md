# Проверка скиллов

Читай, когда проверяешь продукт из скиллов. Это справка для тестировщика,
а не дополнительное чтение обычного этапа. Драйверы проходят один сценарий
в одном хосте; индекс, посев, выбор соседей, проверка записей и сертификат
подключаются отдельно. Настоящие следы и настройки входа храни вне Git.

## Драйверы

Один вызов: `node scripts/skills-run.mjs <request.json>`. Поле `scenario`
принимает объект или путь к JSON-файлу сценария. Пример формы задания ниже;
пути и данные берутся из задания тестировщика, примеры не являются подключением.

```json
{
  "host": "claude",
  "cwd": "/scratch/test-workspace",
  "packRoot": "/scratch/pack-copy",
  "outputDir": "/scratch/evidence/new-run",
  "mcpServers": {"monotest": {"url": "https://example.test/mcp"}},
  "workspaceProof": {
    "tool": "mcp__monotest__get_workspace",
    "path": ["name"],
    "equals": "Test Space"
  },
  "timeoutMs": 1200000,
  "idleMs": 240000,
  "scenario": {
    "prompt": "Пройди этап по брифу тестового продукта.",
    "brief": "Владелец хочет напоминание перед визитом.",
    "allowedTools": ["Read", "Bash", "mcp__monotest__get_workspace"],
    "allowedCommands": ["pwd"],
    "windows": [{"mode": "recommended"}],
    "expectedWindows": [{
      "id": "approval",
      "decision": "напоминание",
      "advice": "Research",
      "reason": "доставку",
      "summary": ["Что", "Дальше:"]
    }],
    "freeQuestions": [{"contains": "Когда напоминать?"}]
  }
}
```

Для Codex: `host: "codex"`, явный абсолютный `authFile` существующего входа
Codex. В новый тестовый дом помещается ссылка на него, не копия токена;
обычные настройки владельца не меняются. По пробе обновление OAuth между
двумя домами не сериализуется: эта оговорка сохраняется в отчёте.
`mcpServers` допускает только monotest и Paper; соединение — `url` либо
`command` и `args`. Дополнительные секреты и произвольные настройки не принимаются
драйвером Codex. Адреса и точный путь доказательства пространства берутся
из предварительной пробы, не угадываются. Paper требует тестового файла и посева
по сценарию Design; наличие соединения само по себе их не доказывает.

`outputDir` должен быть новым каталогом вне репозитория; родитель уже существует.
Сохраняются исходный след, stderr, отправленные ответы, `result.json`; Codex
дополнительно сохраняет stdout и тестовый дом с rollout. Каталог не переиспользуется. Доставка ответа подтверждается результатом
оконного инструмента Claude либо точным сообщением пользователя в новом ходу
rollout Codex; одной записи отправки недостаточно.
Не передавай настройки рабочего дома вместо тестовых. Проверяемая копия пака
уже подготовлена оркестратором; CLI добавляет её локальным маркетплейсом в новый
дом Codex. Версию и фактическую загрузку проверь по живому следу.

Claude запускается с `--strict-mcp-config`, `--plugin-dir` копии,
`--permission-prompt-tool=stdio`; установленный mono выключен настройкой запуска.
Другие инструкции и определения хоста могут загрузиться: это изоляция инструментов,
не обещание стерильной сессии. Вызов вне списка инструментов/буквальных команд
получает отказ; MCP вне monotest/Paper останавливает прогон до разрешения вызова.
Первым идёт чтение пространства; до его совпадения записи запрещены.

Codex запускается `codex exec --json --disable apps` в отдельном доме,
где `[mcp_servers.linear] enabled = false`; удалённые плагины выключены.
Первый ход только на чтение. Продолжение по thread идёт лишь после успешного
чтения monotest. У Codex нет запроса разрешения на каждый инструмент:
проверка вызовов в rollout идёт после хода, нарушение уже могло выполниться.
Это различие хостов принято в T2; такой прогон красный, а не доказательство
отказа до выполнения. В отчёте сохрани точную строку и ссылку на запись,
если она появилась; удаление и проверка записей принадлежат отдельному проходу.

Прямые имена инструментов читаются и из тела `exec` (`tools.<имя>(...)`).
Вызовы через вычисляемые имена не принимаются за проверенные. Команда
`tools.exec_command` принимает полный JSON-объект аргументов с двойными кавычками; поле `cmd`
должно совпасть со списком сценария. Вычисления, неполные объекты и spread
дают отказ аудита. Ограничение добавляется во внутреннее задание этапа. URL в обычном тексте
или имени файла сам по себе не запрещён. Не расширяй список ради зелёного исхода.

Процесс со сбоем, тайм-аутом, повреждённым или оборванным следом не зелёный.
Коды CLI: 0 — транспорт и механические проверки пройдены, 1 — `failed`,
2 — `unverified`. `result.conversation` остаётся `unverified` до рубрики;
код 0 драйвера не сертификат QA и не разрешение вливания.

## Ответы владельца

Порядок окон и ответов задаётся `windows`; отсутствующая политика останавливает
прогон. `recommended` выбирает точный суффикс, `label` — точную метку без суффикса,
`correction` отправляет `text`, `empty` — пустой ответ, `refuse` — заданный `text`,
`discuss` — «Ещё обсудить». Нет нужной метки — отказ, не приблизительный выбор.
Решающие ответы персона не выбирает.

Claude отвечает через `updatedInput.answers` (отказ — `deny`). Codex возобновляет
тот же thread обёрткой `<send_user_message_question_reply>` с полями
`questionItemId`, `question`, `answer` из образцов пробы; голая метка не заменяет
обёртку. Пустой ответ проверен в CLI; формы пустого ответа и отказа приложения
не наблюдались. Ограничение явно остаётся в результате этих политик.

Свободный вопрос допускается только по очередному `freeQuestions[].contains`
в последнем сообщении этапа. После тишины драйвер делает один отдельный вызов
того же хоста с брифом и сообщением этапа. Без совпадения сценария новых реплик
после финала нет. По умолчанию Claude ждёт 240 секунд тишины; Codex ждёт
стабильности rollout, прежде чем решать, что ход окончен. Увеличение ожидания
не исправляет повторяющийся сбой.

У персоны Claude инструменты выключены `--tools ""` и пустым MCP-конфигом.
Codex получает отдельный дом без плагинов/MCP, выключенные инструментальные
возможности, read-only и указание отвечать без инструментов. Любой наблюдённый
вызов инструмента отменяет ответ персоны. Наличие оставшегося встроенного
инструмента зависит от версии Codex: если вызов появился, прогон не засчитывается,
требуется решение по хосту. Ни одной реплики персоны после конечного итога
без заранее указанного свободного вопроса не отправляется.

## Правила окна

`node scripts/skills-trace.mjs <request.json>` принимает `host`, `trace`,
`expectedWindows`, необязательный `rulesRoot`. Правила взяты из
[owner-dialog.md](owner-dialog.md); отпечаток полного файла хранится в
`skills-trace.mjs`. Изменился источник — проверяющий отказывается выдавать зелёный,
пока в том же PR не пересмотрены код, тесты и рубрика. На старой версии пака
для ключа приёмки передавай нынешний `rulesRoot`.

`expectedWindows` фиксируется до запуска. Для каждого окна сценарий указывает
буквальные фрагменты сути (`decision`), совета (`advice`), причины (`reason`)
и полного итога (`summary`). Проверка ищет их в первой строке вопроса и в итоговом
тексте; это не распознавание смысла моделью. Автор сценария выбирает фрагменты,
которые доказывают именно предлагаемое решение; полный смысл проверяет рубрика.
Механически проверяются: один вопрос, максимум три варианта, совет первым,
суффикс, описания последствий «что даёт / чем платим», формат и порядок хоста.
У async строка каждого последствия начинается с точной метки, включая суффикс.

Claude использует общий `claudeWindows` из `skills-probe.mjs`, а не отдельный
разбор границ. `user`, `result`, `system init` сбрасывают текст, дочерние события
не меняют родительский ход. Текст только из размышлений не засчитывается.
Невидимые форматные символы Unicode (`Cf`) и variation selectors сами по себе
текстом не считаются; визуально пустые глифы других классов оцениваются рубрикой.
Итог и окно Claude должны принадлежать одному сообщению без служебных вызовов
между ними. Codex async требует итог после окна последним сообщением хода;
вызов после него даёт `failed`. Нет ожидаемого окна или вместо него текст — `failed`.
Каждое нарушение содержит `evidence` вида `файл:строка`.

Обычный след требует успешного терминального события. `excerpt: true` разрешён
только для проверки сохранённых обезличенных участков, например дефекта :228
и контроля :139; это не доказательство завершения живого сценария.

## Рубрика разговора

Тестировщик читает весь след и выставляет каждому пункту `passed`, `failed`
или `unverified`, указывает точные `файл:строка` и объяснение. Отсутствие
доказательства не зелёный исход. Механический результат не заменяет этот разбор.

- Каждый вопрос содержит конкретный выбор, совет и причину; фрагменты сценария
  не совпали случайно с пустой формулой или цитатой правил. Вопрос по одному,
  суть в одной-двух фразах, у каждого варианта понятны результат и цена.
- Вопросы развивают разговор, не повторяют одинаковое начало и не спрашивают
  уже известное из брифа, предыдущего ответа или прочитанного материала.
- Полный итог находится в видимом чате, содержит позицию, различия и сильнейший
  довод против совета; файл, команда и размышление его не заменяют. Итог следует
  шаблону и пределу слов конкретного этапа из проверяемой версии owner-dialog.
- До окна закончены чтения, помощники, проверки и показ. После окна нет работы
  до ответа, кроме обязательного последнего async-итога. Уведомление помощника
  не ответ владельца. После финала драйвер не спровоцировал лишний ход.
- Пустой ответ, отказ и поправка не стали утверждением и не переоткрыли окно
  автоматически. Изменённый утверждаемый текст показан повторно перед согласием.
- Изоляция подтверждена до этапа; рабочий Linear не использован; сведения о
  неподтверждённых клиентах, Design, OAuth и форме ответа приложения сохранены.
  Проверку самих записей выполняет следующий слой QA, не эта рубрика.

Правила разговора старых версий для ключа оцениваются по нынешней рубрике.
Зелёный рубричный вывод возможен только после чтения доказательств, не по
самооценке этапа или наличию непустого текста. Публикация и общий сертификат
остаются за сессией тестировщика.
