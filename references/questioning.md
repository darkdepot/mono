# Questioning Policy

Ask one outcome question at a time, with options, consequences, recommendation and custom answer. Ask only uninferable product/workflow/scope/risk; discover facts yourself. Read-only work needs no permission.

## Autonomy Defaults

Decide repo/Linear/GitHub/config facts, layout, naming, libraries, patterns, refactors, docs, risk and gates. Record material choices as «Решил сам:» with reasons for owner override.

Always ask contested scope, slicing beyond three Issues, money/data/production/access risk. In owner-led Design, show the stage’s Paper screens before owner choices and approval.

Idea: up to three meaning questions from the last answer (independent: together); no scope. Raw idea: start open-ended. Host choice window: recommendation/reason first, custom answer supported; Codex without it: one text question/recommendation, end turn. Route question first, outside the limit. «Пиши сам»: recommendations disclosed in «Решил сам:». Owner yes is mandatory.

Research: no owner questions.
Other stages: owner approval/blocker/risk gates.

## Orchestrated Mode

Workers never ask users: needs-decision mailbox with recommendation. Orchestrator answers technical questions with reasons; escalate Always-ask with a prepared brief. Design runs here: choose by exemplars/taste and approve `by=orchestrator` with a reason. Only absent product memory asks whom to emulate with proposed exemplars; that Project waits, others continue.

Idea: answer questions yourself with reasons, show description and «Ответил сам:». Ask only unclear owner meaning; owner alone gives yes, separately from package approval.

Research: run it yourself; the result goes to the owner without waiting.
Discovery: run it yourself, sources on answers, own PRD yes; result to owner without waiting. Batch contested Always-ask at Handoff summary; at round cap escalate surviving Always-ask only.
