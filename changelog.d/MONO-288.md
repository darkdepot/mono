### Added
- Драйверы Claude Code и Codex проходят один сценарий с ответами владельца из файла, отдельной персоной для свободных вопросов и сохранением исходного следа. Изоляция и подтверждение monotest проверяются до этапа; ограничение Codex на отказ до выполнения явно отражено.
- Проверяющий следа ловит отсутствующее окно, позицию только размышлением, ошибки карточки и неверный порядок async-итога с точной строкой доказательства. Транспорт требует наблюдаемую доставку ответа; итог Claude не собирается из разных сообщений, дочерние результаты не завершают родительский ход. Короткий вход в mono:qa ведёт к справке и рубрике разговора; обязательное чтение доставки не увеличено.
- Подтверждение исполнения связано с родными полями хоста: аудит команды не принимает подменное поле, первое чтение пространства требует настоящий вызов и связанный успешный результат, ошибка окна не засчитывается доставленным ответом. Недостаток доказательств даёт `unverified`.
- Аудит Codex закрывает неизвестные нативные элементы и экранированный исходник через `unverified`; поздние разрешённые чтения не повторяют строгую форму первого чтения. Нативный `input_text` проверяется обезличенным срезом пробы, ошибки сохраняются при распаковке всех обёрток.
- Ошибка на любом предке пути доказательства пространства или в конечном значении даёт `missing`, даже если прочитанное значение совпало с ожидаемым.
- Окно Codex засчитывается и получает ответ только после связанного нативного результата известной формы `accepted:true`. Отсутствующий, ошибочный или неизвестный результат даёт `unverified`; отправка сообщения не заменяет доказательство появления окна.
