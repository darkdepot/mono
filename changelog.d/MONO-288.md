### Added
- Драйверы Claude Code и Codex проходят один сценарий с ответами владельца из файла, отдельной персоной для свободных вопросов и сохранением исходного следа. Изоляция и подтверждение monotest проверяются до этапа; ограничение Codex на отказ до выполнения явно отражено.
- Проверяющий следа ловит отсутствующее окно, позицию только размышлением, ошибки карточки и неверный порядок async-итога с точной строкой доказательства. Транспорт требует наблюдаемую доставку ответа; итог Claude не собирается из разных сообщений, дочерние результаты не завершают родительский ход. Короткий вход в mono:qa ведёт к справке и рубрике разговора; обязательное чтение доставки не увеличено.
- Подтверждение исполнения связано с родными полями хоста: аудит команды не принимает подменное поле, первое чтение пространства требует настоящий вызов и связанный успешный результат, ошибка окна не засчитывается доставленным ответом. Недостаток доказательств даёт `unverified`.
- Аудит Codex закрывает неизвестные нативные элементы и экранированный исходник через `unverified`; поздние разрешённые чтения не повторяют строгую форму первого чтения. Нативный `input_text` проверяется обезличенным срезом пробы, ошибки сохраняются при распаковке всех обёрток.
- Ошибка на любом предке пути доказательства пространства или в конечном значении даёт `missing`, даже если прочитанное значение совпало с ожидаемым.
- Окно Codex засчитывается и получает ответ только после связанного нативного результата известной формы `accepted:true`. Отсутствующий, ошибочный или неизвестный результат даёт `unverified`; отправка сообщения не заменяет доказательство появления окна.
- Все потребители нативных результатов используют один модуль проверки: чтение пространства, команда, доставка ответа, принятие окна и завершение в обоих хостах. Полный конверт и все слои до доказательства проверяются без исключений для ошибочных квитанций; намеренный отказ Claude отправляется, но его записанный ошибочный результат остаётся `unverified`. Синтетическая таблица отрицательных случаев общая для всех потребителей.
- Единая проверка сохраняет реальные успешные формы: вход Claude сравнивается структурно с сохранением порядка массивов, stdout Bash остаётся данными, отсутствие финального доказательства Codex даёт `unverified`. Положительная таблица проверяет все18 записанных следов и образцов обоих хостов рядом с общей отрицательной таблицей, включая исходные call139/permission140.
- Все поведенческие пути чтения следа используют один закрытый аудит и proof gate: онлайн-драйверы, offline-проверка, оконные helpers, проба и персона. Неизвестные события/блоки и экранированный exec дают `unverified` одинаково; прямые драйверы и обёртка используют единый итог. Таблица одинаковых следов и перечень точек входа закрепляют это правило без нового парсера или расширения форм.
- Полный след, карточка до ответа и явный excerpt различаются общей фазой проверки. Полный Claude-след без permission, с чужим/ошибочным разрешением или без доставки ответа даёт `unverified` во всех поведенческих путях; предответная карточка Codex продолжает работать. Общая таблица сравнивает одинаковые полные/excerpt-входы и сохраняет записанный корпус зелёным.
- Codex требует свежий нативный финал каждого продолжения, включая ответ свободной персоны после обязательного окна. Окно из предварительного подтверждения пространства отклоняется и не заменяет окно сценария; общие формы и аудит не расширены.
- Claude связывает завершение с последним отправленным продолжением через существующее waiting/native terminal gate, включая ответ персоны; выход0 без свежего parent result даёт `unverified`. Общие положительные и отрицательные контроли покрывают stage/free reply/persona обоих хостов.
- Причина различия raw-потоков210 воспроизведена разбиением stdout: fixture продолжала писать окно после намеренно неизвестного элемента, а драйвер останавливался на нём. Fixture теперь завершает такой префикс без последующего окна; строгое сравнение потоков сохранено.
