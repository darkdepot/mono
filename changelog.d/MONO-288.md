### Added
- Драйверы Claude Code и Codex проходят сценарий с шестью политиками окна и отдельной персоной; общий proof gate требует связанные успешные доказательства, доставку ответа и свежий терминал.
- Проверка следа ловит пропавшее окно, итог только размышлением и неверный порядок async-итога со ссылкой на строку. Короткая ссылка из QA ведёт к справке и рубрике без роста обязательного чтения.
- По живым следам список информации открыт: служебные события не останавливают этап; аудит exec читает имена инструментов, команды не ограничиваются. MCP вне monotest/Paper и запись до подтверждения остаются красными; Codex изолирован тестовым домом и серверами.
- Исправлены конфиг отключённого Linear, разрешения тестового MCP, двухблочное доказательство пространства и однократный повтор стартовой гонки. Сценарий завершает процесс после последнего ожидаемого ответа и свежего терминала, сохраняет исходный след и его границу. Полные обезличенные формы обоих хостов проверены через runScenario; настоящий дефект Claude198 остаётся красным.
- Новый parent init Claude требует свежего завершения хода; ответ персоны потребляет свободный вопрос, чтобы продолжение без нового вопроса не получало лишний ответ в обоих хостах.
- Прямые MCP-вызовы Codex сохраняют namespace вместе с именем инструмента: ранняя запись и чужой сервер больше не проходят как обычный инструмент хоста.
- Повтор стартового чтения Codex допускается после аудита всего первого хода: чужой MCP, ранняя запись и оборванное завершение больше не скрываются за повтором.
- Намеренный отказ Claude подтверждается точной связанной квитанцией deny; драйвер продолжает ход и сохраняет реакцию этапа. Другие ошибки не засчитываются.
- Аудит MCP в Codex читает все файлы хода тестового дома, включая дочерние потоки и нативные McpToolCall; доказательства окон и хода остаются только в основном потоке.
- Исправлены привязка завершения Codex к активному turn_id и точные рекомендованные метки. Claude доставляет ответы на все вопросы окна; Codex принимает окна без вариантов и отличает несовместимую политику сценария. ESRCH и macOS EPERM после выхода лидера не добавляют шум к исходной ошибке.
- Выход лидера больше не отключает очистку группы: фиксированная пауза 500 мс ограничивает ожидание дочерних stdout/stderr, тайм-аут остаётся ошибкой. Завершённый сценарий Codex принимается и на последней разрешённой итерации; незавершённый по-прежнему падает, лимит по умолчанию не меняется.
