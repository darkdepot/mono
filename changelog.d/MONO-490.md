Лишняя попытка для задачи теперь записанный шаг, а не локальный конфиг: оркестратор добавляет по одной попытке, только когда лимит задачи исчерпан, и с причиной; выше шести попыток нужны дословные слова владельца. Общий лимит берётся из конфига продукта в основной ветке и не выше шести, а другой лимит в локальном конфиге игнорируется с предупреждением. Каждое добавление помнит лимит, который оно дало, поэтому смена конфига в основной ветке не отменяет уже записанные. Все добавления хранятся рядом со счётчиком попыток и видны в отказе запуска и в выводе `attempt-cap.mjs show`.

Для обновления: после установки задачи, у которых попыток уже больше общего лимита (например, задачи Zeni на 7–9 попытках, поднятые локальным конфигом), перестают запускаться, пока для них не записано добавление: `node '<pack-root>/scripts/orchestrator/attempt-cap.mjs' raise --root <корень оркестратора> --config <конфиг продукта> --issue <KEY> --reason <почему>`. Каждый вызов добавляет одну попытку и проходит только при исчерпанном лимите; выше шести попыток нужен ещё `--owner-words <дословные слова владельца>`, поэтому задаче на 9 попытках, чтобы получить десятую, нужно по вызову на каждую попытку от общего лимита до десяти, и каждый вызов выше шести со словами владельца.
