## MONO-290

- QA продуктов из скиллов подключается через qa.skills: индекс, хосты и perChange; выбор сохраняет пункты сценарий × хост до прохода.
- Записи сценариев сверяются с отдельным свежим дампом monotest по фиксированному перечню и полным цепочкам курсоров. Рабочая запись останавливает suite со ссылкой для ручного удаления; отчёт показывает время и число задач.
- Сертификат связывает id, точный текст и источник ожидания (MONO-279), принимает scenario и запрещает для него excluded/no-behavior. Неполный или unverified исход удерживает существующие ворота.
- Конфиг Mono не менялся; его подключение остаётся задачей полного выпуска после установки промежуточного пака.

Реальные формы Codex/monotest покрыты обезличенными выдержками; посев и промежуточные записи сверяются отдельно, Design требует собственного утверждения и гейта.

Дамп сохраняет драйвер по фиксированной очереди чтений; цепочка продолжает любой unverified, сохраняя его статус. Посев Research и остановка «Ещё обсудить» отделены от отказа Idea.

Сверка Codex берёт ответ на утверждение из нативного следа, не читает журнал отправки как Claude. Реальные выдержки live3 включают журнал и след отдельного дампа; переход к Design проверяется результатом этой сверки.

Live4: сверка учитывает форматирование ссылок, списков и границ блоков Linear, сохраняя различия текста, абзацев и кода. Старт Handoff проверяет собственные кнопки начала и передачи работы, не кнопку утверждения другого этапа.

Находки ревью: утверждение связывается с полями штатной записи и нативным показом версии; текст вне записи его не подменяет. Многострочный inline-код остаётся буквальным, повтор курсора не даёт полному дампу зелёный результат.

Проверки завершения, границ и запрещённых переходов действуют во всех нативных следах. Свежесть дампа требует доказанного начала чтения после всех записей, включая дочерние; без порядка результат unverified. Для Claude без timestamps штатный результат драйвера связывает интервал процесса с хешем сырых событий. Нативные часы live-выдержек сохранены.

Страницы дампа требуют фиксированных аргументов без фильтров и сохраняют их по цепочке. Утверждается последний видимый текст решения; порядок чтения перед native MCP-записью требует связанного начала вызова, иначе unverified. Граница проверки — реальные формы хостов; дальнейшее усиление доказательств порядка остаётся MONO-281.

Live5: различия пустых строк у заголовков и в конце описания Linear больше не дают ложный красный; текст и код остаются строгими. Capacity/host failure дампа даёт unverified и один изолированный повтор с сохранением обоих следов; настоящий write violation не скрывается повтором, unverified продолжает цепочку, сохраняя свой статус.

Live6: expectedRecords и forbidden считают записи через разбор блоков idea-gate в штатном месте этапа. Упоминания mono-design/mono-research в журналах задач больше не дают ложный дубль; настоящий повтор записи остаётся failed.

Live7: успешный посев проверяется по ожидаемому состоянию проекта/маршрута, строгая сверка применяется к записям сценария. Статус сопоставляется по записанному id или имени; shell-items не считаются MCP-записями. Недоступное фиксированное чтение дампа повторяется один раз; только failed останавливает цепочку, любой unverified сохраняется и продолжает её.

Live8: MCP-имена внутри строки shell-команды exec не считаются записями, когда эту строку подтверждает нативный CommandExecution. Настоящие monotest-вызовы остаются строгими, неподдерживаемая форма даёт unverified. Handoff доходит до проверки своего утверждения и route-gate.

Полные имена записей отделены от удалённых скиллов; сокращённые входные типы сопоставляются точно с именами полных маркеров. Запрет удалённых имён в валидаторе сохранён.

Рабочее MCP-чтение сохраняет остановку, но не предлагает удалить существующую запись. Ссылки удаления требуют успешной мутации. Синтетический Claude-хост отправляет завершённый вызов и результат вместе: немедленный abort больше не обрывает отправителя между ними; проверка ссылки сохранена.
