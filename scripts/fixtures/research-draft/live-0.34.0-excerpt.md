## Кратко

Практики сходятся: резать по поведению, которое можно проверить, с «готово, когда» внутри задачи и явными зависимостями; универсального размера нет \[Ф1–Ф6\]. У нас правило другое: по умолчанию одна задача на проект и деление только «если слишком велико» \[Ф10\], а первые пакеты последних проектов получали 3–7 задач и пересобирались чаще из-за правок PRD и Tech Spec выше по цепочке, чем из-за самой нарезки \[Ф12, Ф13\]. Сверка на входе есть только общим правилом «найти существенные расхождения», без того, что считать конфликтом между проектом, исследованием и PRD \[Ф16\]. Главная оговорка: проект без Tech Evaluation по решению владельца пойдёт без Tech Spec, а действующее правило пака запрещает это для сквозных, релизных и затрагивающих данные изменений \[Ф20\]; это правило придётся явно менять.
Уверенность: средняя, потому что практики сходятся и подтверждены нашей историей, но измеренного сравнения «нарезка по PRD против нарезки по техдизайну» не нашли ни у кого.

**Совет:** делать. Определили его решения владельца 17.10 и 19.10 \[Ф14, Ф15\] и то, что действующие правила нарезки и Tech Spec расходятся и с практикой, и с этими решениями \[Ф10, Ф20\].

## Ответы на вопросы

### 4. Что делать с проектами на старом пути

Ответ: старый путь, где Handoff пишет PRD, доступен, только если нет записи «да» на PRD и PRD или одобрение пакета появились до 20.10.2026; настройка продукта может сдвинуть дату \[Ф23\]. Значит, PRD, созданные с 20.10.2026, идут только через Discovery. На старом пути сейчас 3 проекта в Discovery с уже одобренными пакетами; старого PRD без пакета в Discovery нет; в Ready нет никого; ещё 4 проекта со старыми пакетами в Delivery, наличие у них записи PRD не проверяли \[Ф24\]. Их пакеты уже одобрены, новый Handoff им не нужен, пока их не придётся ремонтировать. Видели: \[Ф23, Ф24\]. Уверенность: высокая по числам на 19.10.2026.
