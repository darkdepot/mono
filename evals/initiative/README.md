# Инициатива: срабатывание и проверка поведения

По образцу `evals/tech-evaluation/README.md`: четыре положительных запроса —
сырая идея на несколько проектов, черновая инициатива, повторный вход и проект,
который владелец называет инициативой (этап срабатывает и честно говорит, что
это проект); четыре близких отрицательных — один проект, одна доработка без
проекта, Research проекта, Idea проекта карты. Каждый `<случай>/prompt.md` имеет
тег `initiative` и `graders/initiative-invocation.md` с `tool_used` для `Skill`.
У отрицательных `min: 0`, `max: 0`. Синтетические примеры без личных данных.

Это только срабатывание, не доказательство записей и разговора:

```bash
claude plugin validate . --strict
claude plugin eval . --ablation none --runs 3 --threshold 0.8 --no-publish --trust-plugin
```

Каталог шести этапов `evals/scenarios/index.json` не меняется; Initiative, как
Issue и QA, остаётся `uncovered`. Структуру и чтение проверяют `validate-workflow`
и `node scripts/read-budget.mjs --skill initiative --mandatory` (до 20 480 байт).

## Как проверить поведение

На версии пака с ветки, Linear только тестовый (Mono Test) или чтение. Сохраняй
показанный текст, вопрос, дословный ответ и обратное чтение изменённого.

1. **Честная классификация.** Дело на часы — этап говорит «это задача» с
   причиной и предлагает `mono:issue`; один результат с концом — «это проект» и
   `mono:idea`; ничего не записывает в инициативы.
2. **Разгон, не пересказ.** Сырая идея на несколько проектов: первый ответ по
   существу — черновик по шести частям, в котором есть то, чего не было в словах
   владельца: проблема одной историей, результат как изменение для людей,
   сигнал, ставка с отвергнутой альтернативой и главным допущением, «не делаем».
   Вопрос один и про то, что меняет инициативу.
3. **Без лишних защит.** Каждое ограничение или защита в черновике и карте
   названы вместе с вредом; без вреда их нет. Нет консилиума и второй модели.
4. **Утверждение.** Согласие словами на показанную версию даёт один комментарий
   `mono-initiative: approved` с хешами из обратного чтения, проверка даёт pass,
   статус Planned. Вопрос, сомнение или «да» на уточнение не дают записи.
   Правка в Linear после показа даёт «Было / Стало» и новый вопрос.
5. **Карта срезами.** Ни один проект не назван слоем («база», «интерфейс»,
   «агенты»); первый проходит весь путь и проверяет главное допущение; после
   любого польза остаётся; два-пять пунктов, зависимости только назад.
   Проверь на исходной идее, которую легко нарезать слоями.
6. **Проекты.** После согласия на карту и pass проекты в Idea с привязкой,
   приоритетом, телом пункта и «Зависит от»; «Заведён» в «Решении». Ничего не
   запущено.
7. **Повтор без дублей.** Прерви после `save_project` до «Заведён»: повтор
   находит проект по номеру и ссылке, создаёт только недостающие. Признанный
   существующий проект получает только привязку, приоритет и комментарий
   зависимости.
8. **Повторный вход.** Новая сессия называет сделанное одной строкой,
   продолжает с первого несделанного шага, решённое не переспрашивает,
   показывает состояния проектов по статусу и записи Idea.
