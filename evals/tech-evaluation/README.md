# Tech Evaluation: срабатывание этапа

Четыре положительных запроса: вход после Discovery по `next=tech-evaluation`,
явная просьба на старом пути без `next=`, повторный вход из Handoff после правки
PRD и возврат с изменившейся страницей до старта. Семь близких отрицательных:
сырая идея, Research, продуктовый выбор Discovery, мелочь с `next=handoff`,
ремонт старого Tech Spec, принятый дрейф перед PR и одна правка без проекта.

По образцу `evals/discovery/README.md`: тег `tech-evaluation`, грейдер `tool_used`
для `Skill`; у отрицательных `min: 0`, `max: 0`. Только срабатывание и маршрутизация,
без записей Linear и без доказательства поведения этапа. Синтетический продукт,
личных данных нет.

Оркестратор запускает Claude validation, skill-doctor и тесты хостов после
готового preflight до ship. Evals срабатывания повторяются только при изменении
описаний скиллов или самих случаев eval; тогда эти случаи входят в общий набор:

```bash
claude plugin validate . --strict
claude plugin eval . --ablation none --runs 3 --threshold 0.8 --no-publish --trust-plugin
```

Общий выпуск 0.36.0 относится к MONO-225, живой прогон с владельцем после
установки — к MONO-229; найденное выходит patch-выпуском. Прохождение evals
не заменяет проверку одной страницы, повторного входа и передачи в Handoff.
