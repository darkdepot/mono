# Idea: срабатывание этапа

20 запросов на русском: 13 должны вызвать `mono:idea`, 7 не должны. У каждого
ровно один грейдер `tool_used` для `Skill` с `input_match` на `idea`/`mono:idea`;
отрицательные случаи требуют `min: 0`, `max: 0`. Формат по
[документации Claude Code](https://code.claude.com/docs/en/plugin-evals#grader-types).
Запросы не подсказывают имя скилла. Набор проверяет только маршрутизацию.

Оркестратор или воркер Claude Code запускает из корня пакета на итоговом коммите:

```bash
claude plugin eval . --ablation none --runs 3 --threshold 0.8 --no-publish --output-dir <временная папка вне репозитория>
```

`--ablation none` оставляет грейдер вызова в счёте. Все 20 случаев выполняются по
три раза; каждый должен набрать не меньше 0,8. В PR записывается счёт каждого
запроса, версия Claude Code и проверенный коммит. Полные результаты хранятся вне
репозитория; `evals/results/` игнорируется. Read/Glob/Grep/Skill разрешены для
выбора и чтения этапа; настоящих записей Linear в наборе нет.

Разведчики, вопросы по одному, остановка до записи, статус после «Готово» и
поведение в Codex проверяются живой приёмкой. Для контекста инициативы она
обязательна до вливания по разделу T3 ниже. Этот набор
такого поведения не доказывает. В Codex проверки Claude не запускаются:
оркестратор возвращает результаты до ship.

## Контекст инициативы: проверка поведения

Три новых запроса `linked-map-project`, `map-candidate`, `no-initiative`
проверяют только выбор Idea. Поведение ниже проверяется отдельно на версии
пака с ветки; успешный `tool_used` и текст инструкции его не доказывают.
Сохраняй показанное описание, вопрос, дословный ответ владельца, исходное тело
и обратное чтение связей/брифа по UUID. Worker не пишет напрямую в Linear.

1. **Проект карты привязан.** Дано: тестовый проект из T2 в Idea, привязан,
   тело из строки К1 и «Зависит от», трёх разделов и брифа нет. Когда владелец
   начинает Idea и уточняет результат иначе, чем в карте, тогда Idea называет
   связь, читает описание инициативы и полное «Решение», опирается на цель,
   модель и место в карте. Описание следует словам владельца, не копии карты;
   отдельное согласие словами, не утверждение инициативы. После согласия
   прежнее двухстрочное тело целиком в «Отброшено» брифа, связь сохраняется,
   запись Idea проходит прежний verify/check. Карта и зависимости не меняются.
   Отрицательная проба: до согласия нет замены тела или записи Idea.
2. **Новый проект похож на пункт.** Дано: идея и похожий пункт без привязанного
   проекта. Когда разведка находит его, тогда Idea говорит «похоже», читает
   контекст и спрашивает принадлежность. Ответ «да» только на этот вопрос
   не утверждает описание. После подтверждения и отдельного согласия на
   описание один save_project создаёт проект с addInitiatives; обратное
   чтение инициативы с includeProjects содержит UUID нового проекта.
   Отрицательная проба: «нет, это самостоятельный проект» — связи нет.
3. **Существующий проект без связи.** Дано: проект в Idea, найден похожий
   пункт. Когда владелец подтверждает принадлежность и описание, тогда тот же
   UUID получает addInitiatives, другие связи сохраняются, статус/владелец
   не меняются. Повтори после сбоя между записью связи и брифа: проект один,
   связь читается обратно и не создаётся заново. Уже привязанный проект
   не требует повторного подтверждения принадлежности. Переименование
   не меняет сопоставление. У уже утверждённого проекта с прежним описанием
   подтверждение принадлежности добавляет только связь с обратным чтением,
   не создаёт дубля approval и не требует заново утвердить прежнее описание.
   Два кандидата или недоступный документ — пробел
   назван до утверждения, за владельца связь не выбирается.
4. **Без инициативы.** Дано: обычная идея без связи и кандидатов. Когда
   владелец проходит Idea, тогда прежние вопросы, четыре раздела, бриф,
   согласие словами и verify/check без addInitiatives; инициатива не создаётся,
   разговор сам в новый этап не переносится. Отрицательная проба: не считать
   ошибку чтения Linear доказательством отсутствия инициативы.

## Живой прогон T3 до вливания

Владелец начинает Idea на проекте карты тестовой инициативы из T2 в команде
Mono с версии пака с ветки и словами утверждает описание. Ссылки на тестовые
сущности передаёт оркестратор комментарием в MONO-261. После прогона он пишет
«Живой прогон: …» в задаче; без этого комментария готовности к вливанию нет.
Затем тестовая инициатива T2 и её проекты переводятся в Canceled оркестратором.
Модельные evals срабатывания и непроверенные хосты сообщаются отдельно;
они не заменяют участие владельца и обратное чтение.
