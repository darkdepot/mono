# Design: срабатывание этапа

Пять положительных запросов явно называют mono:design: первый продукт, фича,
правка на месте, повторный вход по PRD, возврат техлида с пунктом на экранах.
Пять близких отрицательных: сырая идея, Discovery, отсутствие интерфейса,
задача кода без проекта и прежний маршрут при выключенном этапе.

Сейчас этап спит: явный вызов только читает его правила и останавливается,
без создания задачи, Paper и новых записей. Положительный грейдер проверяет
выбор скилла, не разрешает выполнить его спящее тело. После общего включения
MONO-228 эти же явные запросы проверяют срабатывание рабочего этапа; добавление
неявного входа относится к включению, а не к MONO-227.

По образцу evals/tech-evaluation: тег `design`, `tool_used` для `Skill`, у
отрицательных `min: 0`, `max: 0`. Только срабатывание и маршрут, не поведение
памяти, картинок или согласия. Продукт синтетический, личных данных нет.

Оркестратор запускает на выпуске MONO-229 после включения:

```bash
claude plugin eval . --ablation none --runs 3 --threshold 0.8 --no-publish --trust-plugin
```

Живой прогон всей цепочки у владельца и оркестратора относится к MONO-229;
неподходящий макет, пункт на экране и пункт вне экрана проверяются там отдельно.
Зелёные evals не доказывают качество макетов и не заменяют живой прогон.
