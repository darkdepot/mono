# tech-evaluation: empty

Проверять весь след, а не самооценку этапа. Для каждого пункта passed, failed или unverified и ссылка файл:строка.

- Целевые окна узнаются по меткам роли и совпадают с expectedWindows своего хоста; каждое обязательно. Промежуточные окна не сдвигают политику цели: рекомендованный ответ при вариантах, персона без вариантов. Все они проверены по общим правилам и записаны. Текстовый обход цели не зелёный.
- Суть и совет с основанием в вопросе, рекомендованный первым, последствия у каждого варианта, не больше трёх; вопрос по одному. Семантику совета проверяет эта рубрика, якорь его не заменяет.
- Вопросы не повторяют бриф, источники, известные решения и одинаковое начало.
- Итог цели следует шаблону tech-evaluation и лимиту слов owner-dialog проверяемой версии. У промежуточного выбора своя суть и совет; четыре раздела утверждения ему не требуются. Видимый итог и порядок обязательны: thinking, файл или команда его не заменяют.
- Все записи только в проекте текущего run id пространства monotest. Версии берутся обратным чтением; опубликована показанная версия, нет дублей. Независимая сверка записей выполняется следующим слоем QA.
- Пустой ответ или обсуждение не стали согласием/стартом. То же окно не переоткрылось автоматически. У Codex последующее свободное окно не подменяет исходное утверждение.
