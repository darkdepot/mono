# Проба хостов

Материалы MONO-287, захвачены оркестратором 30.10.2026 UTC: Claude Code
2.1.311, Codex CLI 0.159.2, копии Mono v0.38.1 и v0.41.0 из тегов.
Это входы для следующих задач, а не индекс сценариев или драйвер этапов.

## Локальная проверка

```bash
node --test scripts/skills-probe.test.mjs
node scripts/skills-probe.mjs evals/scenarios/probe/samples/claude/trace-defect-v0.38.1-approval.json
node scripts/skills-probe.mjs evals/scenarios/probe/samples/claude/trace-control-v0.41.0-approval.json
```

Скрипт переносит узкую проверку живой пробы `window-check.py`: ищет видимый
текст текущего хода перед верхнеуровневым `AskUserQuestion`. Любое новое
верхнеуровневое событие `user` (строка, блоки или результат инструмента),
`result` или `system` с `subtype: "init"` сбрасывает накопленный текст.
Между ходами `user` может отсутствовать; остальные события `system` границей
хода не считаются. Видимый текст содержит
хотя бы один символ, отличный от пробелов, форматных символов Unicode (`Cf`)
и variation selectors. Дочерние события проверяются на повреждения до пропуска,
но их текст и окна не учитываются. Содержимое размышлений на вердикт не влияет, в том числе
когда оно скрыто. Принимает исходный Claude stream-json (JSONL) или сохранённый
образец `{events: [{line, event}]}`. Ничего не запускает и никуда не пишет.
Путь передаётся явно; исходные следы держат вне репозитория.

Выход: JSON с `check`, `status`, `windows`, `boundary`; каждое окно содержит
`evidence` вида «файл:строка», `toolResult`, `textLines`, `thinkingLines`.
Коды: 0 — текст найден перед всеми наблюдаемыми окнами; 1 — окно без текста;
2 — окно не достигнуто, вход повреждён или недоступен (`unverified`).
Каждое событие должно быть объектом с непустым строковым `type`;
повреждение конверта или используемых полей отменяет весь результат, даже
если до него найдено окно. Неизвестные типы событий допустимы.
Результат относится только к этому признаку: наличие текста не доказывает
полноту итога, качество вопроса, ответ на окно или безопасность прогона.

Образец дефекта: результат инструмента :187, размышление :227, окно :228,
ответ «Ещё обсудить» :230. Контроль: текст :138, окно :139. Дефект пойман
на **утверждении**, окно выбора варианта в том прогоне содержало текст.
Это не доказательство узкого повтора дефекта именно на выборе варианта.
В образцах оставлены выбранные события и исходные номера строк с пропусками;
полный след и проверка полноты остаются доказательствами хоста.

`trace-turn-boundary-v0.41.0.json` — обезличенный участок реального потока
:286–294 без `user`: текст :286, `result` :288, `system init` :290,
размышление :293. В репродукции QA вызов Bash на :294 заменён на
`AskUserQuestion` из контрольного образца; это тестовое окно, не наблюдённое
окно хостового прогона. Оно должно дать `failed`, не используя текст :286.
Личные метаданные опущены, текст и размышление заменены плейсхолдерами.

## Образцы ответов

В `samples/claude/` и `samples/codex/`: `recommended`, `label`, `correction`,
`empty`, `refuse`, `discuss`. Они сохраняют запрос, отправленный ответ и то,
что получила модель. Claude: `control_request` → `control_response` с
`updatedInput.answers`, отказ через `deny`; Codex: аргументы async-окна из
rollout, ответ новым сообщением через `exec resume`.

`codex/app-reply-form.json` — наблюдённая форма выбора в приложении;
`questionItemId` содержит JSON-массив имени инструмента, call id и индекса
вопроса. Выбор по метке через resume даёт ту же структуру. Пустой ответ
проверен в CLI как `answer: ""`, но в приложении такая форма **не наблюдалась**.
Отказ в CLI — обычное сообщение; отдельная форма отказа приложения неизвестна.
Оговорки сохранены в `note`. `trace-control-v0.41.0-async-order.json` показывает
окно перед итогом в последнем сообщении хода, без нового проверяющего Codex.
Его `function_call_output` сохраняет наблюдённое тело `{"accepted":true}`.
В срезе нет идентификаторов вызова: тестовые обёртки добавляют синтетический
совпадающий `call_id` для проверки связи вызова с результатом. Отрицательные
ответы в регрессиях намеренно изменены и не являются наблюдёнными отказами хоста.

`codex/workspace-input-text.json` — срез результата из тестового дома пробы,
rollout 31.10.2026 01:43:52, строка 21: один блок `input_text` с успешным чтением
пространства из четырёх блоков нативного результата `exec`. Обёртка пробы сохранена,
id, имя и адрес пространства обезличены. Срез проверяет декодирование блока;
он не доказывает, что весь многочастный результат поддержан драйвером.

Обезличивание: аккаунты, идентификаторы пространств, вызовов, сообщений,
запросов, подписи и личные пути заменены плейсхолдерами. Номера строк, версии,
типы событий и структура ответов сохранены. Полных следов, настроек подключения
и данных рабочих продуктов здесь нет. Регрессионный тест читает каждый образец.

## Граница живой пробы

По отчёту хоста изоляция подтверждена до первого этапа; Idea на v0.41.0
прошла окно, ответ, запись и обратное чтение в обоих хостах. Аудит не нашёл
вызовов MCP за пределами тестового Linear и Paper. Это сведения отчёта хоста,
а не результат локальных тестов или самостоятельная проверка исполнителя.

Открытые развилки перед следующей задачей остаются у оркестратора:

- Paper обнаружен обоими хостами, но Desktop не работал: Design, тестовый файл
  и посев памяти `unverified`; требуется решение владельца и при необходимости
  ремонт R2/R3 через Discovery. Невозможность фонового Design не доказана.
- Изоляция приложения Codex конфигом тестового проекта не подтверждена:
  постоянный пробел и вопрос владельцу в каждом выпуске.
- Чтение основного Linear во время и после прогона есть; новое чтение до
  старта и настоящее обновление OAuth не наблюдались. Проверка ссылки входа
  не доказывает безопасность одновременного обновления из двух домов.
- Idea заняла 163 с в Claude и 152–157 с в Codex; новых задач в пробе 0.
  Проверка одной правки целиком не замерена; оценку расхода нельзя выдать за замер.
- В момент пробы в тестовом Linear не было статусов проектов пака: Research
  остановился. Перед MONO-288 оркестратор сообщил, что статусы уже заведены;
  эта справка не является новым живым чтением. Проверка записей и ворота отдельно.

Полный отчёт, ссылки на живые записи и решения по развилкам оркестратор
публикует в комментарии проекта. Локальный зелёный тест не снимает пробелы
и не заменяет сертификат текущей версии перед вливанием.

plus the two-block workspace output and unavailable-tool startup race. Tool arguments
and text are neutral replacements; event ordering and proof linkage remain explicit.

adds a declared synthetic task_complete of the recorded form, not observed live success.
