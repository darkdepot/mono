# Проверка разговора

Ready, пакет и задачи готовы до вопроса о старте. Согласие записывает старт ровно показанной версии и набора задач; делегирование только по прямым словам.

Неясный ответ приводит к уточнению, без утверждения или старта.
Проверяй настоящий нативный ответ, запись и независимое обратное чтение.
Вызов окна, вопрос в рамке хоста или одинаковая концовка разных этапов — провал.

Обязательная рубрика U7: summary — итог соответствует нативно прочитанному документу, а не только якорям; question — фактический вопрос соответствует заранее заданной роли; response — реакция соответствует фиксированному исходу без лишнего вопроса/перехода; correction — правка действительно внесена по смыслу, только в названном месте. Отрицательные варианты сохраняют якоря: обратный смысл итога, отказ внести правку и предложение перехода без имени этапа должны дать failed; недоказанное соответствие — unverified. Ожидаемый исход рубрика не меняет.

Бриф: нативно прочитан документ по строке «Бриф:» записи Idea, с блоком mono-brief этого проекта. Summary проверяет конкретную опору из брифа и отметку переспроса уже сказанного, если он был; формальная фраза без опоры не проходит. Недоказанное чтение — unverified.
Correction (AE2): сравни исходный бриф посева и все нативные записи/чтения до и после ответа без утверждения. «Суть сейчас» (кроме «Открыто»), «Решения и повороты» и «Отброшено» остаются прежними; новая идея может быть только вопросом в «Открыто». Даже временная правка сути без согласия даёт failed; отсутствие исходного тела или цепи правок — unverified.
До записи пакета сверены бриф и последнее действующее утверждение (PRD, при ремонте действующий утверждённый пакет); тихое расхождение снимается со ссылкой на это утверждение, этап пропущенного решения и исправление названы в итоге без отдельной остановки. Неутверждённый новый пакет не основание менять суть.

Контроль ремонта класса 3 применяется только к прогону, в котором действительно произошёл такой ремонт. В этой ветке: прежнее согласие на пакет снято, затем Discovery утвердил новый PRD и обновил бриф. Handoff сохраняет новую утверждённую суть и ссылается на действующее утверждение PRD; восстановление требований отменённого пакета, даже временное, даёт failed. До нового утверждения предложение остаётся в «Открыто»; при действующем согласии на пакет сверка с ним сохраняется. Нет доказательства состояния согласий и обратного чтения — unverified.

Два случая проверки этого контроля: первый Handoff без ремонта проходит без доказательств ремонта, если остальные проверки сценария пройдены; это не доказывает покрытие ветки ремонта. Если ремонт класса 3 произошёл, отсутствие доказательства состояния согласий или обратного чтения даёт unverified; возврат требований отменённого пакета даёт failed, даже при верном названии этапа и ссылке.

Ссылки согласия в строках брифа (поворот, «Отброшено», старт) содержат полный Linear URL проекта или задачи с #comment-<uuid>. Голый UUID или «комментарий проекта <uuid>» даёт failed, даже если id правильный. При снятии расхождения summary явно называет этап, чьё утверждённое решение было пропущено; исправленный бриф без названия этапа в самом итоге даёт failed. В посеве approve это Discovery. Недоказанный текст ссылки или итога — unverified.

Формат дописанного брифа: только разделы «Суть сейчас», «Как это видит владелец», «Решения и повороты», «Что знаем», «Отброшено»; решения этапа в «Решения и повороты». Дата строки — ДД.ММ.ГГГГ; ссылка согласия — полный Linear URL записи проекта или задачи с #comment-<uuid>. Любой заголовок вне этих пяти (например, «## История» или «## Решения»), дата «2026-11-08» или иной формат вместо ДД.ММ.ГГГГ, голый id либо URL проекта или задачи без #comment-<uuid> дают failed даже при верном смысле решения. Строка 08.11.2026 с полной ссылкой записи в правильном разделе проходит этот контроль, если остальные проверки пройдены; новый допустимый раздел вместо ранее пустого разрешён. Проверяй нативное тело/патч и обратное чтение, а не обещание формата; недоказанный формат — unverified.
