# Проверка одной задачи

Проверяй настоящие задания и ответы обоих проверяющих, версии черновика,
точечную перепроверку, прочитанную запись и старт. Обещания и синтетические ответы
не доказательства. Недоступное доказательство — unverified, неверное — failed.

- Пакет: одна задача tiny; короткая запись с прежними mono-package: recorded,
  входами и хешем. Решения исполнителя сжаты в U, покрытия R/U сохранены,
  задача называет номера без пересказа. Кратко одна фраза, Сверка только с
  решениями, T1 несёт поведение, места, покрытие, проверку.
- Оба реальных проверяющих прошли один полный круг до записи. Tiny advisory,
  отсутствие второго проверяющего или второй полный круг — failed.
- Начальный дефект null против R2 найден проверяющим как блокирующий P0/P1
  по сути; исправление даёт прочерк, тот же автор перепроверил только эту
  находку и снял её. Пропуск проверки или полное ревью вместо точечной — failed.
  Отсутствие нужной находки — unverified, не выдумывай успех из исправленного текста.
- Хотя бы одна находка о названии отмечена самим нашедшим «по формулировке»;
  его названная правка применена без нового круга. Без отметки считай по сути;
  чужая переклассификация — failed. Подлинный ответ не получен — unverified.
- Блокирующая не отклонена доводом «так было раньше»; отклонение допустимо
  лишь доказанным опровержением из источника. Неблокирующие имеют диспозицию.
- До вопроса о старте Ready, пакет и задача готовы; согласие записывает
  ровно показанную версию, один старт, с обратным чтением.

Обязательная рубрика U7: summary соответствует прочитанному пакету и содержит
конкретную опору «Источник»; question — настоящий контекстный вопрос о старте;
response — реакция на фиксированное согласие без лишнего вопроса/перехода;
correction — внесены только заявленные правки, требования PRD неизменны.
Обратный смысл при сохранённых якорях, отказ исправлять или переход без имени
этапа — failed; недоказанное соответствие — unverified. Окон и одинаковых
концовок этапов нет. Ожидаемый исход рубрика не меняет.

Бриф прочитан по строке «Бриф:» записи Idea, mono-brief свежего проекта;
после старта обновлён только по согласию с полным URL записи #comment-<uuid>,
датой ДД.ММ.ГГГГ в одном из пяти разрешённых разделов, прочитан обратно.
Этот сценарий проверяет ревью нарезки; исключение встречной проверки
by=orchestrator, другие риски и несколько задач им не доказаны.
