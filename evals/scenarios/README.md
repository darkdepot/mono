# Сценарии этапов

Читай только при проверке продукта из скиллов. Обычные этапы каталог не читают.
`index.json`: закрытый список общих файлов, файлы этапов, имена этапов (`name`), соседи, основной
сценарий и короткая цепочка. Каталог содержит только Mono. Пути внутри него
относительны индексу; правила `files` относительны Git-корню продукта, суффикс
`/` означает каталог. Другой продукт передаёт свой индекс тем же параметром.
`templates/qa-output.md` не относится к общим файлам разговора.

## Выбор до прохода

`node scripts/skills-select.mjs <request.json>`:

```json
{
  "indexFile": "/copy/evals/scenarios/index.json",
  "worktree": "/copy",
  "base": "origin/main",
  "head": "HEAD",
  "output": "/scratch/selection.json"
}
```

Выбор только по committed `base...head`. Каталог внутри репозитория должен
совпадать с `head`. Изменённый этап получает все свои сценарии, соседи основной
путь; общие файлы и общие данные каталога выбирают все этапы. Удалённый сценарий
нельзя скрыть удалением ссылки из индекса. Отсутствующий файл, неверная форма
или удаление дают ошибку, а не уменьшенный зелёный набор. Для первой версии
каталога отсутствие индекса на базе допустимо. Индекс вне продукта также
принимается; история удалений для него остаётся в репозитории его владельца.

`selection.json` создаётся эксклюзивно и хранит `head`, merge base, digest всех
данных/рубрик/guard, выбранные сценарии, цепочки и `expectedItems` для обоих
хостов. Этот список не выбирается сертификатом. Интеграция с `qa.skills`,
`task-expected.json` и сертификатом принадлежит следующей задаче.

## Запуск на хосте оркестратора

`node scripts/skills-suite.mjs <request.json>`:

```json
{
  "selectionFile": "/scratch/selection.json",
  "indexFile": "/copy/evals/scenarios/index.json",
  "runId": "mono-289-check-1",
  "outputDir": "/scratch/mono-289-check-1",
  "cwd": "/scratch/mono-test-product",
  "packRoot": "/copy",
  "authFile": "/explicit/codex-auth.json",
  "mcpServers": {"monotest": {"url": "https://mcp.linear.app/mcp"}},
  "paper": {"fileId": "<request parameter>", "command": "paper", "args": ["mcp"]},
  "designMemoryFile": "/explicit/test-product/memory.md"
}
```

`cwd` — отдельный тестовый продукт с латинским `projectName` и конфигом Mono,
не рабочая папка владельца. Перед запуском оркестратор проверяет, что
`designMemoryFile` относится к этому тестовому продукту и путь соответствует
его slug в `idea-gate`. Реальный id файла и настройки подключений не коммитить.
Paper уже открыт, тестовый файл создан и содержит страницу «Как на проде»;
новых эталонов у владельца сценарии не спрашивают. `paper` не передавать напрямую
в `mcpServers`: suite сам ставит guard из индекса вторым сервером. Нет fileId:
стоп до хоста. Все tools/call guard требуют этот id; файловые инструменты без fileId,
создание, переименование, перенос и архивация недоступны. Справка `get_guide`
также требует id на входе реле; после проверки он снимается, поскольку API Paper
для справки принимает только `topic`. Справка не обращается к файлу. Даже у необязательного
fileId в Paper-схеме guard делает его обязательным. Методы вне tools также закрыты.

Suite сначала создаёт `expected-items.json`, затем каждый драйвер сам подтверждает
пространство настоящим чтением до первой записи. Имя каждого проекта латинское
с run id, хостом и сценарием. Idea не получает посева и создаёт проект только
после согласия. Остальным первый вызов сеет записи по рецепту инструментами
monotest и генератором пака, берёт id/версии только обратным чтением. Заготовки
не содержат реальных id, дат версий или чужих продуктов.

Основной путь изменённого этапа: основной предыдущего соседа, сам этап,
основной следующего; `next` задаёт маршрут на каждом касании. Этапы идут отдельными
сессиями в одном проекте, в том числе Design. Первое чтение сохраняет указатель
`{id,name,url}`, последующие сверяют его перед записью. Каждый этап записывает
свой файл в новой папке `.mono-skills-<runId>-*` внутри `cwd`; suite копирует
проверенный файл в каталог результатов. Нет файла от текущего этапа или сменился
проект — цепочка останавливается. Основные утверждения могут выбрать «продолжу позже», затем драйвер
явно начинает следующий этап. Research проверяет именно старт или обсуждение.
Другие сценарии и оставшиеся соседи получают собственный проект/посев. При
нескольких изменённых этапах сосед может проверяться в разных контекстах цепочки;
каждый такой пункт заранее виден в ожиданиях, не теряется из отчёта.

Данные окон разделены по хостам. `idleMs=20000`, бюджет по умолчанию 30 минут,
`maxTurns` больше числа окон. У Codex есть подсказки свободных текстовых вопросов
для персоны, а у пустого ответа ожидается также последующее свободное окно.
Непредусмотренное окно — красный/непроверенный исход, а не автоматический ответ.
Якоря первой строки окна закрепляют только форму: «Утвержд», «Совет» и имя
следующего этапа; для перехода — «Начин» или имя следующего этапа. У старта
Handoff следующий этап не задан: проверяются «Начин» и «Совет». В цепочке имя
следующего этапа берётся из индекса по фактическому `next`, включая переход
Discovery → Tech Evaluation. Семантику
решения, причины совета и качество разговора проверяет `rubric.md` по полному следу. Известный дефект MONO-292
остаётся красным; сценарий не просит перенести итог из размышлений обходом.

`suite-result.json` сохраняет каждый ожидаемый пункт. После сбоя этапа остаток
цепочки `unverified`, а не исключён. Указатель проекта не доказывает полноту
или правильность записей; независимый дамп и сверка — следующий слой. Механический
`passed` также не заменяет рубрику и не является сертификатом QA.

## Проверка

`node --test scripts/skills-catalog.test.mjs`: форма всех сценариев, точные соседи,
локальный Git diff, общий файл, посторонний файл, удалённый сценарий, альтернативный
индекс, ожидаемый список до вызова, короткая цепочка в обоих адаптерах, отрицательные
проверки guard через поддельный MCP-процесс. Синтетический драйвер доказывает
порядок вызовов, не живое поведение этапа. Живую короткую цепочку в обоих хостах
проходит оркестратор; из worker хосты/Paper не запускаются.
